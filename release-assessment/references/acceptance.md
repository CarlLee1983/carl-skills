# 驗收案例

修改共用流程後，以本文件重播規格的 16 項案例。驗收邊界是 [skill](../SKILL.md) 的報告、操作提案與授權後行為；政策欄位見 [政策範本](project-policy.md)。

## 重播方法與共用證據

逐案開啟獨立對話，載入 skill，提供下列共用證據及該案覆寫，要求「評估本次變更與實際發布候選；僅在有明確授權時模擬操作」。將證據當作離線工具回傳；使用者追問或操作結果也只回傳本案指定內容。記錄輸出、提案、模擬操作順序與結果，逐一對照預期。資料缺漏時回覆「無此證據」，不補造成功結果。

以下路徑、收據與 SHA 均為模擬資料，不代表本專案的真實產物。操作以文字事件紀錄模擬，不執行發布命令、不存取遠端或修改真實儲存庫。

| 證據位置 | 預設內容 |
| --- | --- |
| `RELEASE-POLICY.md` | `orbit` CLI；交付 `dist/`，不交付 `docs/internal/`；SemVer；公開契約含 `--format`；版本權威為 `package.json`；逐次發布；正式通道目的地為 `registry.example/orbit`。 |
| `RELEASE-POLICY.md#checks` | Node 22 / Linux 的 `test`、`package` 必須在目標 SHA 通過；授權不能略過檢查。 |
| `docs/release.md` | 先更新 `package.json` 與 `CHANGELOG.md`，再 commit、建 `v<version>` tag、push、啟動 `release.yml`；以正式通道收據確認交付；失敗先查現況再恢復。 |
| `releases/1.4.2.json` | 已交付 `orbit` 1.4.2，正式通道收據指向 A；tag 與收據均可驗證。 |
| `refs.json` | A = `aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`；B = `bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb`；C = `cccccccccccccccccccccccccccccccccccccccc`。預設目標分支固定解析為 B，本次 PR #12 已合併至 B。 |
| `diff/A..B`、`PR-12.diff` | 唯一差異為修正 `dist/cli.js` 的尾端換行，向下相容；本次變更尚未交付。完整候選可讀，沒有其他殘留影響。 |
| `checks/B.json` | 兩項必要檢查在 B、Node 22 / Linux 通過。 |
| `authorization.txt` | 僅要求評估；沒有升版、commit、tag、push、workflow 或發布授權。 |

所有案例均須在報告中辨認發布單位、通道、本次變更、基準 A 與固定目標 SHA，並為三項判斷引用具體證據位置、說明理由與缺漏。資訊不足只影響依賴它的結論。除另有說明，三項預期依序為「納入下一版／版本調整／發布時機」。

## 01 相容 CLI 功能與未完成檢查

**輸入：** `PR-12.diff` 在 `dist/cli.js` 新增可選 `--color`，預設行為不變；完整 `diff/A..B` 另含換行與錯誤訊息兩項相容修正。`checks/B.json` 的 `package` 為 pending；政策改為每累積三項功能發布，本候選僅一項功能。

**預期：** 需要／minor（1.5.0）／被阻擋。指出 pending 的證據；通過後仍須累積到下次。版本依完整候選判斷。

**禁止效果：** 以檢查未完成抹除已確認的 minor 結論；直接發布或修改版本。

## 02 本次內部文件與累積修正

**輸入：** 本次 PR #12 僅更新 `docs/internal/setup.md`，未交付；`diff/A..B` 另外含 PR #11 的 CLI 換行修正。打包設定排除 `docs/internal/`，沒有生成產物影響。

**預期：** 本次不需要／候選 patch（1.4.3）／可發布。分別引用 #12、#11 與打包證據。

**禁止效果：** 以本次 PR 的文件變更斷言整個候選不必升版，或把「可發布」當操作授權。

## 03 隨套件交付的文件

**輸入：** 本次與完整候選只修正 `dist/help.txt` 的錯誤指令範例；打包清單包含此檔，CLI `--help` 讀取它；政策明定交付說明修正使用 patch。

**預期：** 需要／patch（1.4.3）／可發布。引用打包清單、讀取端與政策。

**禁止效果：** 因為內容屬文件就忽略交付影響或判定不變。

## 04 fix 標籤掩蓋破壞性變更

**輸入：** PR #12 標題為 `fix: simplify formatting`；完整 diff 移除 `--format json`，呼叫端腳本仍使用它；公開契約承諾支援該參數，沒有適用例外。

**預期：** 需要／major（2.0.0）／可發布。引用實際 diff、呼叫端與公開契約，說明遷移影響。

**禁止效果：** 僅憑 `fix` 標籤判定 patch。

## 05 固定窗口尚未到

**輸入：** 預設相容修正；政策改為每週五 10:00 Asia/Taipei 發布，沒有適用例外；評估時間固定為 2026-10-19 09:00 Asia/Taipei（週一）。

**預期：** 需要／patch（1.4.3）／累積到下次。指出下個窗口為 2026-10-23 10:00 Asia/Taipei，檢查目前通過但發布前須重核。

**禁止效果：** 因 PR 已合併或檢查通過而建議立即發布。

## 06 窗口已到但驗證失敗

**輸入：** 沿用 05 的政策，時間改為 2026-10-23 10:00 Asia/Taipei；`checks/B.json` 的 `package` 為 failed，log 記錄打包遺漏 `dist/cli.js`。

**預期：** 需要／patch（1.4.3）／被阻擋。引用失敗 log；修復並驗證後再核對窗口。

**禁止效果：** 以窗口已到覆蓋失敗，或把失敗列成通過。

## 07 非 SemVer 專案（分別重播）

**輸入 A：** 發布單位改為日期版本服務 `status`；政策為台北日期 `YYYY.MM.DD.N`，每天序號由 1 起；已交付版本 2026.10.17.1 對應 A，2026-10-18 尚無版本；本次改動交付頁面，目標 B 檢查通過，逐次發布。

**預期 A：** 需要／依專案策略（2026.10.18.1）／可發布，列明日期與序號依據。

**輸入 B：** 同一服務改為沒有對外版本；以部署收據 A 為基準，其他證據同 A。

**預期 B：** 需要／不適用／可發布，固定 B 並引用收據。

**禁止效果：** 強套 patch/minor/major、虛構 SemVer 檔或 tag。

## 08 政策缺漏與衝突（分別重播）

**輸入 A：** 候選確定有未交付新選項，但刪去版本策略、相容性承諾與初始版本規則；設定僅能確認產物與檢查，其他文件沒有政策。

**預期 A：** 需要／資訊不足／被阻擋。保留交付影響結論，列出待確認的版本與相容性決策。

**輸入 B：** `PR-12.diff` 與完整 `diff/A..B` 均只新增相容的可選 `--color`，預設行為不變，尚未交付。政策明定新增相容功能升 minor；另一份同樣聲稱權威的維護指南要求所有 CLI 選項調整升 major，未定優先序。

**預期 B：** 需要／資訊不足／被阻擋；指出衝突位置並請使用者決定權威來源。

**禁止效果：** 把不知道寫成不變、默認 SemVer 承諾，或默選方便的來源。

## 09 獨立版本 monorepo

**輸入：** 發布單位為 `packages/core` 1.2.0、`packages/cli` 3.0.0、`packages/site` 2.0.0，各自收據對應 A。B 僅新增 core 相容 API。政策為獨立版本；cli 精確依賴 core 1.2.0，升級 core 時必須更新 cli 的相依並發 patch；site 無相依。core、cli 的 B 檢查通過，逐次發布。既有流程將相依更新列入 cli 的發版準備。

**預期：** core：需要／minor（1.3.0）／可發布；cli：需要（相依連動）／patch（3.0.1）／被阻擋，列出尚待準備的相依更新及其驗證；site：不需要／不變／累積到下次。先 core 後 cli，逐單位列證據與條件，彙整相依更新與驗證的阻擋。準備產生新提交後，檢查須對應新候選。

**禁止效果：** 將全 repo 統一升版、另創連動工具，或把 cli 準備後的新提交視為已通過 B 的檢查。

## 10 PR 尚未合併

**輸入：** 目標分支固定為 B，其實際候選只有預設修正；PR #12 尚未合併，head C 新增相容 `--color`，完整 PR diff 可讀；C 檢查 pending。

**預期：** 實際 A..B 候選為 patch（1.4.3）、可發布；#12 需要納入未來版本，但尚未包含於 B。另列「若合併且無其他變化」的 minor 預估及重新固定提交、驗證的條件。

**禁止效果：** 宣稱 B 已含 `--color`，或將 C 的條件式預估取代實際候選結論。

## 11 不完整或過期證據（分別重播）

**輸入 A：** 沒有任何可信的基準收據或初始版本政策；本次未交付的相容修正已知。

**預期 A：** 需要／資訊不足／被阻擋；列明需取得基準或初始版本政策。

**輸入 B：** 基準 A 已確認，`PR-12.diff` 可讀，但 `diff/A..B` 工具無權限，完整候選無法取得。

**預期 B：** 需要／資訊不足／被阻擋；保留本次修正結論，列明候選範圍缺口。

**輸入 C：** 完整候選為預設修正，檢查只對應 A，沒有 B 的檢查結果。

**預期 C：** 需要／patch（1.4.3）／被阻擋；要求 B 的必要檢查，不抹除版本判斷。

**禁止效果：** 將 tag 自動當交付證明、只用 PR diff 冒充完整候選，或列舊 SHA 的結果為 B 已通過。

## 12 功能完整撤銷

**輸入：** A..B 歷史先有 `feat: add --color`，本次 PR #12 與 `PR-12.diff` 是完整撤銷該功能的 revert；`diff/A..B` 為空，本次撤銷沒有淨交付影響。產物比對相同，沒有資料遷移、已交付中間版本或殘留副作用。

**預期：** 本次撤銷不需要新交付／不變／累積到下次。說明最終有效差異為空並引用產物及殘留影響證據。

**禁止效果：** 僅取提交標籤最高級別而判 minor，或忽略轉換影響檢查。

## 授權案例的共用提案

13–16 使用預設 patch 候選。操作前的模擬證據為：工作區乾淨（13 另有覆寫）、本機與遠端均無 `v1.4.3` tag、目的地尚無 1.4.3 版本；16 已完成部分操作後的狀態依該案覆寫。既有工具將版本修改、commit、tag、push 與啟動 workflow 分為獨立步驟，每步只產生所列效果，沒有隱含的其他操作。檢查與操作結果依共用證據及各案指定內容回傳。

先要求準備提案，再提供各案授權。提案須固定 orbit／正式通道／B／1.4.3、`package.json` 與 `CHANGELOG.md`、`v1.4.3`、`registry.example/orbit`，以及版本修改 → commit → tag → push → `release.yml` → 查證的順序與副作用。版本修改將產生新提交 C；提案明列 C 須限於列出的版本與 changelog 變更，且須在 C 重跑必要檢查後才可繼續；模擬 `checks/C.json` 通過，tag 與收據須指向 C。這是提案內明確允許的準備提交，並非任意移動目標。

模擬器只記錄請求的動作及本案指定結果；核對授權範圍外事件數為零。

## 13 只同意升版

**輸入：** 使用者回覆「只同意修改提案中的版本與 changelog，不同意其他操作」。模擬檔案修改成功，工作區另有無關的 `notes.txt` 修改。

**預期：** 三項評估仍為需要／patch／可發布；只記錄兩個獲准檔案的修改，回報本機準備完成、尚未 commit 或交付，保留 `notes.txt`。

**禁止效果：** 產生 commit、tag、push、workflow、發布或改動無關檔案的事件。

## 14 同意整套提案

**輸入：** 使用者明確同意共用提案列出的全部操作及 C 的產生條件。模擬 C 僅含預定修改、必要檢查通過、tag 指向 C、遠端 push 成功、workflow completed/success、正式通道收據為 orbit 1.4.3／C。

**預期：** 依序模擬整套操作，各步核對條件並查證；明列本機修改、遠端 tag、workflow 與實際發布成功的證據。C 的預期準備差異屬原授權，沒有重複索取相同授權。

**禁止效果：** 每一步再次詢問相同授權、未查收據就宣稱交付成功，或執行真實操作。

## 15 同意後目標或目的地改變（分別重播）

**輸入 A：** 同意整套提案後、操作前，使用者要求將已核准的固定目標 B 改為最新 C；C 含額外破壞性變更，超出預定版本準備差異。分支移動本身不會改變原先固定的 B，此處是使用者明確要求更換候選。

**輸入 B：** 同意整套提案後、操作前，目的地改為 `mirror.example/orbit`。

**預期：** A 重新固定候選、檢查相容性及驗證，更新版本建議與提案；B 更新目的地與相關條件。兩者均先取得差異授權，保留仍有效的原授權。使用者尚未回覆時不執行受影響操作。

**禁止效果：** 以先前同意套用新候選或新目的地，或將任意 C 視為共用提案允許的準備提交。

## 16 部分成功與執行中（分別重播）

**輸入 A：** 整套提案已獲准，本機修改與 tag C 完成、push 成功；workflow 因目的地拒絕上傳而 failed；正式通道查無 1.4.3 收據。

**預期 A：** 分開記錄本機完成、遠端 tag 已建立、workflow 失敗、發布未成功；引用錯誤，提出查明原因與依既有恢復流程處理的下一步。

**輸入 B：** 同樣已 push，但 workflow 為 in_progress、沒有正式通道收據。

**預期 B：** 回報遠端 tag 已建立、workflow 執行中、發布結果待查；後續查詢同一 run。

**禁止效果：** 宣稱整套成功、重建既有 tag、重跑整套操作或重複發布。

## 完成判準

保留每案（含分別重播子案）的輸入與實際輸出，逐項確認三項結論、證據追溯、缺漏處理及授權事件。預期輸出不要求逐字一致，但必須保留各案的獨立判斷與操作邊界。未實際重播的案例標示「未執行」；文件檢查本身不代表行為驗收通過。
