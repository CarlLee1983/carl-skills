# 專案發布政策範本

建立或補齊專案政策時使用。將以下範本複製到專案根目錄的 `RELEASE-POLICY.md`；已有權威文件的欄位直接填入連結與適用章節。範本空白代表尚待確認，並非預設政策。不同發布單位的差異分別填寫。

```markdown
# 發布政策

## 發布單位與交付內容
- 名稱、路徑、交付型態與產物：
- 文件是否隨產物交付：
- 發布目的地與通道：

## 版本策略
- SemVer／日期版本／沒有對外版本：
- 版本權威來源與更新方式：
- 基準 release 的識別方式與初始版本規則：
- 0.x、預發布與其他例外：

## 公開契約
- 承諾相容的 API、CLI 參數、設定與資料格式：
- 相容性判準、棄用與遷移規則：

## 發布節奏
- 逐次／累積／固定週期，以及觸發條件：
- 緊急修正或其他例外：

## Monorepo（適用時）
- 統一版本或獨立版本，以及發布群組：
- 相依套件的版本與發布連動規則：

## 發布流程與必要檢查
- 既有發布文件、workflow、版本工具與 changelog 規則：
- 必要檢查、適用提交及可接受的驗證結果來源：
- 升版、建立 tag、發布各自的既有步驟：
- 失敗恢復或撤回流程：
```

填寫後確認每個發布單位的基準可對應到已交付提交、必要檢查可對應到候選提交及環境，並能辨認三種操作的既有流程。仍缺漏的欄位保留為資訊缺口；來源衝突且會改變結論時交由使用者決定。

政策只記錄專案規則；評估與授權流程沿用 [release-assessment](../SKILL.md)。填好政策或得到「可發布」建議，均不構成操作授權。
