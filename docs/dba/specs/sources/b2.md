## B2 最終確認稿（待使用者確認，尚非 Resolution）

本稿彙整本票兩輪已確認的七項決策，補齊最低證據、批准交接與 B4 行為驗收。核准對象是 B2 規格，不是實作、建立資源或執行切換的授權；不代表任何情境已通過實測。

### 1. 評估入口與責任

每次開始前選定「角色／拓樸」「指定時間窗內的 Replication 健康」「HA 設定」「指定切換演練或事件驗證」的一項或多項，固定必要主張、最低證據與適用條件。未選項標「本次未評估」，不能因缺證據自行移除必要主張。

輸入記錄資源與節點識別、環境、引擎與版本、部署形態、複製方式及通道、預期角色／關係、參考時間與時區、觀察起訖，以及指定演練／事件與新觀察或歷史證據。必要主張涉及多個節點或通道時，列出完整評估範圍；單一節點觀察不代表全拓樸。

專案指定的資料／服務負責人確認 lag 門檻、觀察窗、取樣間隔與覆蓋要求、證據時效、查詢負載預算、逾時條件、RPO／RTO、量測起訖與服務恢復標準。資料／應用負責人確認關鍵資料、業務不變條件及事件截點的驗證基準。另列有權批准者、人工執行者與證據交回責任人。

Role Skill 可提出政策建議，但不自行套用通用達標數字。缺政策或基準時保留可判讀觀察，無法據此判定的相關主張為 indeterminate，不抹去其他已有充分證據的結論。

### 2. 分層與範圍

引擎層涵蓋 PostgreSQL、MySQL、MariaDB 的自管與 AWS RDS 環境，由 dbcli 執行計畫內唯讀觀察。平台層僅涵蓋 RDS，不含 Aurora；自管及其他平台的未涵蓋平台層主張為 indeterminate 並交人。

新切換演練使用隔離環境，建立、設定、故障注入、切換、流量調整、回切／重建及清除皆由人執行。正式 RDS 環境可準備 runbook 與人工交接，不承擔即時事故指揮或自動操作。自管平台的切換／故障管理 runbook 不在 v1 規格範圍內。

可選定可追溯的歷史演練或正式事件進行事後評估，不強制重演。結論限定當次環境、拓樸、操作與驗證條件；另列目前版本、設定、節點、端點與應用基準變更造成的適用性缺口，不把歷史成功升格為目前能力。

### 3. 必要主張與最低證據

以下是共用契約，依實際引擎、版本、複製方式與部署形態選用適用證據，不能把其他引擎／版本的欄位語意直接移植。

| 主張 | 最低證據與判定界線 |
| --- | --- |
| 角色／拓樸符合預期 | 已確認的預期拓樸、資源／節點身分、時間、實際角色與來源／接收關係。平台與 SQL 證據須對應同一對象；有未解決相關矛盾時不能判符合。不以 read-only 設定或單一連線成功推導全部角色。 |
| 觀察窗內複製符合健康要求 | 已確認政策、覆蓋指定時間窗的合格樣本、相關通道運作／錯誤、來源與接收／套用進度、具語意及單位的 lag，以及取樣缺口。依政策分別判 lag、進度與錯誤等必要子主張，不把單次 0 當整窗成功。 |
| WAL／binlog 保留風險符合要求 | 適用的保留設定、slot／複製位置或日誌使用量、可取得的容量與時間序列，以及已確認的風險界限。缺少必要資料時不能宣稱安全；不由瞬間使用量推估未經驗證的耗盡時間，也不延伸為通用容量預測。 |
| HA 設定符合要求 | 同一資源適用的部署種類、成員／AZ／角色與設定、取得時間及已確認的配置要求。平台旗標可支持相應設定主張，不證明 standby 即時健康或實際切換成功。 |
| 指定事件完成預期角色／端點轉換 | 事件／演練識別、操作或平台事件紀錄、前後資源／角色／端點觀察、起訖時間及一致的對象鏈。平台完成訊息不自動證明應用恢復或無資料損失。 |
| 指定事件資料驗證符合要求 | 與該事件資料截點相容的關鍵資料／業務基準及驗證結果。通用筆數、摘要或連線成功不自動充分；需要寫入的探測由人按批准計畫執行並交證據。 |
| 指定事件符合 RPO | 已確認目標與事件參考時間、可證實的資料復原點／遺失範圍或足以判定的界限、基準與計算依據。lag 秒數、LSN／GTID 差值不能直接冒充業務資料損失或 RPO；界限不足以判達標／超標時為 indeterminate。 |
| 指定事件應用恢復／符合 RTO | 應用驗證基準與結果，及政策定義的開始／結束時間。應用恢復與 RTO 分別判定；分開保留平台操作耗時、應用恢復及必要驗證總耗時與等待區段，不能刪除等待來美化 RTO。沒有應用證據不宣稱服務 RTO 達標。 |
| 切換後複製／HA 保護恢復至要求 | 新拓樸、必要複製／HA 設定與切換後指定觀察窗的健康證據。提升為 primary 或恢復服務本身不代表保護能力已重建。 |

Replication 健康與切換驗證都是必要子主張的摘要，不新增單一成功狀態。選定後按適用性事先固定必要子主張；不適用的項目記錄理由，不能事後以不適用掩蓋缺證據。

### 4. 觀察、證據與結果

每次蒐證是有明確起訖、取樣與負載預算的有限任務，不建立持續監控或存取。樣本記錄取得時間與訊號本身的時間、來源、對象、通道、單位與判讀語意。比較不同採集時刻的資料時，須有符合政策的時間對齊或區間界限，不當作同時快照；統計快照／快取、NULL、哨兵值、缺樣與無寫入期須依來源語意解讀。

證據充分性不按指標數量計算；同源的兩個指標不自動構成獨立佐證。看不到 RDS Multi-AZ DB instance standby 的 SQL 訊號，不證明沒有 HA；平台設定也不補足缺失的複製健康證據。查詢失敗或無權不能當成沒有節點／通道。

沿用 ADR-0045：先檢查必要 capability 與 contract 版本；不支援的 schemaVersion 停止整個工作流程，必要 capability 非 available 停止受影響步驟。不得以獨立蒐證繞過版本停止規則，availability 不是批准。

沿用 ADR-0046：充分且無相關矛盾的證據先判 met／not-met；否則相關證據矛盾為 indeterminate，再判必要步驟受阻為 blocked，其餘不足為 indeterminate。等待人工批准／執行與 capability 不可用分別記原因、解除條件及交接人；缺 AWS CLI／唯讀 IAM 為 indeterminate。輔助查詢受阻不掩蓋已有充分證據的 not-met；必要證據保存失敗且無合格替代時，相關主張為 indeterminate。

沿用已定的 CALL 政策：拒絕所致的無法取得觀察為 indeterminate，交既有授權人員取證，不升權、不自動換 AWS API 或原生客戶端。不禁止原本已列入計畫的 RDS 唯讀 API 觀察。平台、原生權限、資料基準或人工證據缺口不自動變成 Tool 缺口。

目標身分不明時停止對該目標查詢；負載或逾時預算到達時停止該觀察，不自行無限延長。安全且獨立的唯讀評估可繼續，但不能改原時間窗讓結果通過。結果保留各主張、理由、混合狀態與缺口；只有全部必要主張為 met 才宣稱本次固定範圍內全部符合。

證據依 ADR-0046 保存來源、取得時間、環境／對象、可追溯引用及可取得的來源 ID；檔案附內容雜湊，敏感原始資料使用受控引用。歷史結論不覆寫；重新評估產生新紀錄，證據過時、不可取得或適用性不足時依本次證據判定。

### 5. 操作類型、批准與交接

runbook 按實際部署區分 RDS Multi-AZ DB instance 切換、Multi-AZ DB cluster 切換、read replica promotion，以及後續回切／重建，不把它們當成可互換操作；同時區分計畫內操作與已發生故障的事後評估。只有引擎／版本／部署形態實際支援的操作才可列入待執行計畫；不虛構通用 failback 命令。

每種操作列出適用前置證據、平台限制與專案政策，明示哪些由平台負責、哪些須人工確認。計畫內 promotion 的來源寫入停止、資料追平與流量轉移不能直接套成所有 Multi-AZ 切換的 SQL 證據門檻。原 primary 已故障或 standby 不可見時，不編造證據，也不把未知當作無資料損失。

交接前確認：

- 目標、計畫版本、操作適用性、有效批准、執行者與責任人。
- 新演練隔離、避免誤接正式流量與不預期外連、資料與連線存取限制。
- 流量／連線重建、寫入控制及避免兩邊接受應用寫入的責任與可用證據；必要條件缺失時不宣稱具備安全切換條件。
- 預期影響、資料損失／停機風險、費用、安全停止方式、不可逆性或回復限制、時間窗、重試範圍與驗證計畫。

批准點設於人工建立／變更／故障注入／切換／回切重建／清除前。單一有效批准可明確涵蓋多個步驟，無須重複取得同一授權；每步仍核對目標、前置條件與批准適用性。超出範圍、實質變更、過期、撤回或未確認資格時停止相關交接，依 ADR-0047 重新批准。工作流程批准、dbcli gate 與 DBA 結論互不替代。

必要前置條件未成立時，runbook 可保留缺口與解除條件，但不可標為可執行。人工接手時重新核對批准與證據時效；批准不自動觸發操作。人工及平台事件分別保存紀錄：事後評估自動平台事件不偽造事前人工批准；人工操作缺少批准紀錄不能因結果成功而補稱已獲准。操作合規與技術主張仍分開記錄。

執行後交回操作紀錄、平台事件、前後身分／拓樸／端點、關鍵時間點、資料／應用驗證、保護能力恢復及殘留資源情況。撤回或停止不等於回滾；已開始的操作由人依計畫安全處理。清除前確認目標、刪除範圍及必要證據已保存；清除或重建失敗明示殘留狀態、原因、接手人，不宣稱已收尾，也不抹去已成立的歷史切換結論。

技術依據：RDS promotion 後 replica 成為獨立 instance，不能假定一鍵撤銷；AWS 建議 promotion 前啟用並完成備份，但明示不能 promotion 的狀態是 backing-up。若專案另要求備份，須標成專案政策，不冒充平台硬限制（[AWS promotion 文件](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_ReadRepl.Promote.html)）。Multi-AZ failover 的 DNS 與連線恢復也有獨立影響，不能以平台完成替代應用驗證（[AWS failover 文件](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/Concepts.MultiAZ.Failover.html)）。本段釐清研究材料，未新增「備份已完成」為所有 B2 操作的通用前置要求。

### 6. B4 行為驗收矩陣

| 情境 | 預期行為 |
| --- | --- |
| 全部所選必要主張的證據齊全、適用且無矛盾 | 僅宣稱本次固定範圍內全部符合；未選項仍本次未評估。 |
| 角色／拓樸符合，但 lag 超標、複製停止或錯誤 | 依充分證據分項 met／not-met，保留混合結果，不由角色正確掩蓋健康問題。 |
| 單次 lag 為 0，但接收／套用進度或通道證據不足／相反 | 不由 0 直接判健康；依適用且完整證據判 not-met，未解決相關矛盾／不足為 indeterminate。 |
| 無寫入期、NULL／哨兵值、快取／快照或時間對齊問題 | 依來源語意與其他證據判讀，不把值機械地當成健康／故障；不同節點／通道／時刻不得直接當同一快照比較。 |
| 缺政策、缺樣、資料過時、觀察被負載或逾時預算截斷 | 不延長／縮小範圍求通過；保留可判讀量測與充分的失敗證據，其餘不足主張為 indeterminate。 |
| WAL／binlog 保留風險超標，或必要容量／進度證據缺失 | 充分違反證據為 not-met；不足為 indeterminate，不把 lag 低當作保留風險安全。 |
| 平台啟用 HA，但 standby SQL 不可見 | 設定主張按平台證據判定；不宣稱 standby 健康、沒有 HA 或切換已驗證。 |
| SQL 與平台角色矛盾、部分通道／節點缺失 | 未解決相關矛盾為 indeterminate；部分可見不代表全拓樸。身分不明則停止該目標查詢。 |
| 平台切換成功，但應用仍連舊端點／資料驗證失敗／保護未恢復 | 角色轉換、應用、資料、RPO、RTO、保護恢復分別判；充分失敗證據與不足證據區分，不給單一「成功」。 |
| RPO／RTO 界限不足、起訖不相容或沒有應用證據 | 保存量測與界限；不足以判定者為 indeterminate，不以 lag／平台耗時冒充服務目標達標。 |
| 套錯操作類型、舊 primary 寫入控制未確認、隔離不足 | 停止受影響的執行交接，列解除條件與接手人；不要求不可見節點提供虛構 SQL 證據，不擴張自管平台範圍。 |
| 批准拒絕／過期／撤回／資格不明／超範圍重試 | 停止未開始的相關步驟；已開始操作交人依安全停止計畫處理，不假設回滾；等待批准與執行分開。 |
| capability 非 available 或版本不支援 | 前者阻擋必要步驟，後者停止整個流程；不繞過既有 gate。 |
| CALL 拒絕、AWS／IAM 缺失、原生查詢無權或失敗 | 按既定政策與證據順序判定，不把觀察缺口當成節點不存在或複製故障，不升權或自動替代執行。 |
| 歷史成功但目前拓樸／版本／應用基準改變；或評估平台自動事件 | 保留歷史結論及目前適用性缺口；自動事件不偽造人工批准，也不將事後評估視為即時指揮授權。 |
| 清除／重建失敗或必要證據保存失敗 | 明示未收尾／保護缺口與接手人；無合格替代證據的相關主張為 indeterminate，不由命令成功掩蓋。 |

### 7. Tool 缺口與後續交付

本票未確認新增原子 Tool 缺口，不代表所有必要能力已實測。既有研究的 partial、真實 RDS、原生最小權限、版本差異與 replica／切換演練限制保留。

各引擎必要觀察、實際 capability ID、contract 版本與證據取得方式，由既有的[各工作流程的 capability 需求與 Tool 缺口定案](https://github.com/CarlLee1983/dbcli/issues/255)逐項對照。只有證據顯示必要行為缺少原子工具能力時才列為候選缺口；不虛構 ID、不把人工批准、應用基準、平台可見性或 CALL 政策改寫成 dbcli 功能需求。

本票核准後，將 B2 驗收證據與測試環境策略從地圖的未指定事項轉成獨立決策票；本 session 不繼續解該票。具體 Skill、runbook 範本與可執行查詢的交付屬地圖之後的規格化與實作，不在本票製作。
