## B2 驗收證據與測試環境策略 — 最終確認稿（待全文確認，尚非 Resolution）

本稿整合本次 wayfinder 訪談 Q1–Q9 已確認的決策；Q7–Q9 由使用者最後一輪「全部照建議」確認。具體化 [B2 Replication／HA 工作流程規格](https://github.com/CarlLee1983/dbcli/issues/252#issuecomment-6258869583) 的驗收策略，沿用其必要主張、結果優先序、有限觀察、安全停止、人工批准與交接，不重開已核准行為。

本票只決定驗收策略，不表示 Skill 已實作、環境已具備或測試已通過；不授權建置、帳號設定、故障注入、切換、清除或發布。本票完成仍需使用者對全文確認。B1／B3 各自驗收，不由本票替代。

### 1. 分階段門檻與結果用語

- **行為候選版**：全部必要行為案例及其必要分支通過，才可稱「B2 行為驗收通過，實環境驗收未完成」，附逐項缺口。尚未全部通過只能報告進度。
- **完整 B2 驗收**：行為驗收、下列本機／RDS 最低實證、可追溯證據、owning repo 所需 gates，以及對同一候選內容的人類驗收審查均完成。聲明明列實際版本、模式、拓樸與操作範圍，不代表所有資料庫組合均已驗收。
- **發布授權**：與驗收分開，本票不授權發布。

行為測試 PASS／FAIL、單一 DBA 主張 met／not-met／blocked／indeterminate、實環境覆蓋範圍三者分開記錄。正確判出 not-met、blocked 或 indeterminate 可使對應行為測試 PASS，不能證明資料庫主張 met，也不能抵銷必要實環境證據缺口。未執行不算 PASS。部分環境通過可逐項陳述，但整體仍保留未完成狀態。

### 2. 最低環境、模式與操作覆蓋

**L：隔離自管引擎實證**，三引擎各一組 primary＋replica 基線：PostgreSQL 實體串流複製、MySQL 與 MariaDB 各自原生非同步複製。各自經 dbcli 以預定受限帳號驗證身分、角色／關係、適用的進度／lag／錯誤與 WAL／binlog 保留風險觀察。

三引擎均需有依批准計畫由人準備的正常、lag、複製停止與恢復觀察，包含有活動與無寫入期；保留觀察起訖、取樣間隔、負載／逾時預算、來源語意與實際缺樣。可採低負載的受控方式產生可辨識 lag，不要求壓垮服務或耗盡儲存；是否超標按該案例事先確認的政策判定。agent 只執行計畫內唯讀取證。

MySQL、MariaDB 除單通道外，各有一次真實雙通道案例：兩條同時存在且身分可區分，觀察正常狀態，以及一條停止、另一條健康／前進和其後恢復；保留各來源、通道及適用的 GTID／domain 範圍。兩次單通道取樣不能冒充雙通道。PostgreSQL 其他複製模式及未實測拓樸明列未驗收；多節點遺漏的行為分支仍用 fixture 覆蓋。自管僅驗引擎層，不把本機實證升格為自管平台切換／故障管理驗收。

**R：真實 RDS／合格歷史事件實證**，最低八組引擎×操作路徑：

| 操作路徑 | PostgreSQL | MySQL | MariaDB |
| --- | --- | --- | --- |
| Multi-AZ DB instance 切換 | 必要 | 必要 | 必要 |
| Read replica promotion | 必要 | 必要 | 必要 |
| Multi-AZ DB cluster 切換 | 必要 | 必要 | 不適用 |

Instance 切換、cluster 切換與 promotion 各自驗證，不互相替代。八組是證據路徑數，不是必須同時存在的環境數，也不表示只需八次工具呼叫。可分時建立、共用 B1 資源或抵用適用的歷史證據；B1 通過不替代 B2 觀察。Aurora、其他雲平台及自管平台層不在範圍。

每組在後續實作 Story 開始時，依當時支援情況固定完整引擎版本、區域、部署形態、複製模式、設定、預期拓樸、權限、dbcli／AWS CLI 與 capability contract 版本。自管與 RDS 不假設可取得相同 patch。只對實測組合主張已驗收；不將全部通道變體與八條路徑做完整交叉組合，未驗組合另列。無可用區域／版本是缺口，不得將必要路徑改記為通過。

平台依據：[AWS Multi-AZ 部署差異](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/Concepts.MultiAZ.html)、[Multi-AZ cluster 引擎／區域支援](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/Concepts.RDS_Fea_Regions_DB-eng.Feature.MultiAZDBClusters.html)。後續實作仍須核對當時支援情況。

### 3. 每條 R 路徑的最低證據鏈

每條路徑至少一次實際完成預期角色／端點轉換，並有一次恢復至事先指定複製／HA 保護要求的正向實證及後續有限觀察窗。需要重建或回切時按操作適用性另列人工步驟及批准範圍，不假設 promotion 可一鍵撤銷，也不強迫每種操作都回到原拓樸。

每份證據連結：

1. 事件／演練識別、操作類型、來源／目標與前後節點／拓樸／端點、時間及對象對應。
2. 新演練的隔離檢查、批准、人工操作、寫入／流量／連線控制責任與交接；平台事件另存。歷史自動事件不偽造人工批准；人工操作缺批准不因結果成功而補稱合規。
3. 原計畫內的 RDS 唯讀平台觀察與 dbcli 引擎觀察、適用設定／事件／CloudWatch 及可見性限制。Multi-AZ instance standby 不可查詢的限制不能用本機 replica 取代，也不要求虛構 standby SQL 證據。
4. 事先確認且與事件截點相容的資料／業務基準、資料驗證結果、應用恢復基準與實際驗證。需寫入的應用探測由人執行並交回證據；只有連線成功不足。
5. 足以判定的 RPO／RTO 目標、參考時間、資料復原點／遺失範圍或界限、起訖及計算依據。平台耗時、應用恢復、驗證與等待區段分開記錄，不刪除等待美化結果。lag／LSN／GTID 不冒充業務資料 RPO。
6. 切換後保護要求、新拓樸／設定與指定觀察窗，以及清除批准核對、人工收尾或殘留資源／原因／責任人與後續交接。

角色轉換、資料、應用、RPO、RTO、保護恢復各自判定。RPO／RTO 超標可正確判 not-met，不要求業務目標一定達標；證據不足仍有驗收缺口。實際資料／應用失敗保留其結論，不以平台完成掩蓋。

若切換後一度保護未恢復，保留該時段 not-met／indeterminate 及理由；後來恢復另立有時間範圍的新結論。只有「切換完成但保護未恢復」不足以滿足本票的保護恢復正向門檻。清除失敗須明示未收尾，不抹去已成立的歷史主張；殘留狀態與交接完整記錄，不虛稱資源已清除。

合格歷史演練／事件可抵用相應實證，但逐項審查來源、版本、拓樸、通道、設定、權限、資料／應用基準與當前用途的適用性。歷史技術結論與操作合規分開；不把過去成功當成目前能力，也不能免除當前候選 Skill 的行為驗收。

### 4. F：實際 Skill 行為驗收與十六類 B4 對照

F 為可重跑的合成案例／fixture，驗證真正 Role Skill 的判讀、工具選擇、停止、交接與輸出，不只測旁邊的判斷函式或人工閱讀示例。明示合成來源、時間、政策與資料基準；受控工具替身攔截外部效果並完整記錄嘗試的呼叫。

以下每列及其必要分支均需 F；L／R 欄是額外實環境事實，不可用 F 補成實證。精確異常值、矛盾、缺樣、危險誤接、批准撤回及清除失敗可用 F，無須在實環境刻意造成危險。

| B4 情境 | F 必須驗證的行為與分支 | L／R 的必要實證與限制 |
| --- | --- | --- |
| 1. 所選必要主張證據充分 | 只宣稱固定範圍符合；未選項仍本次未評估，不能事後縮小範圍 | L 正常取證；R 八路徑各有必要證據鏈，各主張按實測判定，不強迫 RPO／RTO met |
| 2. 角色正確但 lag 超標、複製停止／錯誤 | 三種失敗分支分開，保留混合結果 | 三引擎 L 有正常、lag、停止與恢復；真實錯誤樣式按實際取得範圍，其他用 F |
| 3. lag 為 0 但進度／通道不足或相反 | 充分失敗與矛盾／不足分開，不由 0 判健康 | L 保留實際進度、來源時間與 lag 語意；指定矛盾用 F |
| 4. 無寫入、NULL／哨兵、快取／快照、時間對齊 | 各分支依來源語意，禁止跨節點／通道／時刻混算 | L 活動／無寫入期及版本適用觀察；未出現的特殊值不能宣稱真實重現 |
| 5. 缺政策／缺樣／過時／預算截斷 | 分開驗證，不延長或縮窗求通過；保留充分失敗證據 | L／R 保存實際觀察預算、樣本與缺口；精確截斷分支用 F |
| 6. WAL／binlog 風險超標或證據缺失 | 超標 not-met、必要資料不足 indeterminate；不從低 lag 推論安全 | L／R 取得適用設定、位置／用量與觀察；不要求耗盡儲存，超標可 F |
| 7. HA 已啟用但 standby SQL 不可見 | 設定與健康／切換分開；不可見不等於沒有 HA | R 真實 Multi-AZ instance 的平台設定及可見性限制，不能由 L 替代 |
| 8. SQL／平台矛盾、部分節點／通道缺失 | 矛盾 indeterminate；部分可見不當完整；身分不明停止查詢 | L MySQL／MariaDB 雙通道及混合健康狀態；R 對應同一對象的來源，合成矛盾不當實證 |
| 9. 平台成功但舊端點／資料失敗／保護未恢復 | 各分支及必要子主張獨立判，區分失敗與不足 | R 保存資料／應用與保護證據，含保護恢復正向門檻；故意誤接／損壞用 F |
| 10. RPO／RTO 界限不足、起訖不相容、缺應用證據 | 各分支保存量測，不能用平台耗時／lag 冒充服務目標 | R 需要可判定量測與應用證據；超標可 not-met，缺證據仍列缺口 |
| 11. 錯操作類型、寫入控制未確認、隔離不足 | 各停止點及解除條件；不擴張自管平台範圍 | R 正確操作、隔離、寫入控制責任與交接；危險分支 F |
| 12. 批准拒絕／過期／撤回／資格不明／超範圍重試 | 各分支停止，已開始交人安全處理，不假設回滾 | R 保存適用批准及執行紀錄；不要求真實撤回中的危險操作 |
| 13. capability 非 available／契約版本不支援 | 必要步驟阻擋與整個流程停止分開；無繞過 | L／R 留存前置檢查、實際版本；不支援分支 F |
| 14. CALL 拒絕、AWS／IAM 缺失、原生無權／查詢失敗 | 原因分開，不當節點不存在或複製故障，不升權／自動替代 | L／R 受限帳號正反例；平台與引擎權限分列，CALL 拒絕不證明程序可用 |
| 15. 歷史成功但拓樸／版本／應用基準改變，或平台自動事件 | 歷史結論與目前適用性分開；自動事件不偽造批准 | 使用歷史 R 時逐項審查，不能免當前 F；不要求為此引發真實事故 |
| 16. 清除／重建失敗或必要證據保存失敗 | 分別驗殘留／保護缺口與保存不足；無合格替代時相關主張 indeterminate | R 保存實際收尾、殘留與交接及證據可取得性；失敗分支 F |

共同交叉案例包含混合主張、有充分 not-met 但輔助查詢受阻、矛盾與受阻並存、必要證據保存失敗有／無合格替代，以及黑名單／列數保護／權限造成不完整可見。沿用 B2／ADR-0046 的優先序，不另創狀態：充分且無相關矛盾先 met／not-met；否則相關矛盾 indeterminate，再判必要步驟受阻 blocked，其餘不足 indeterminate。CALL、AWS／IAM 等特定缺口仍按既定政策，不一律改成 blocked。

### 5. 權限、TLS 與工具邊界

L 與 R 以預定受限帳號完成正常取證，並保留安全的權限不足案例。RDS IAM 與引擎原生權限各自驗證；可用人事先批准／準備的受限身分或適用既有紀錄，不由 agent 撤權、升權、改帳號或複製 ambient 憑證。高權限成功不能替代受限帳號驗收，受限帳號成功也不直接證明「最小原生權限」。

沿用[各工作流程的 capability 需求與 Tool 缺口定案](https://github.com/CarlLee1983/dbcli/issues/255#issuecomment-6259411027)：按實際操作檢查必要 capability 與契約；available 不證明握手、原生權限或完整可見性。TLS 必要目標須滿足明確設定、CA 信任與主機名驗證；`connection.tls` 是該決策要求後續交付的能力，不在本票宣稱已交付。缺能力或設定就保留缺口，不靠 ambient 行為、明文或停用驗證繞過。

CALL 拒絕政策不變，不自動改用其他工具；原計畫內 RDS 唯讀觀察可照計畫執行。不得放寬 agent mode、blacklist、write gate 或 production 選擇來完成驗收。

### 6. 重跑、留存、缺口與更新

每個必要 F 案例固定可重建 Skill 內容、fixture／預期行為、工具契約、模型識別與可控制設定、runner 版本，以全新 session 至少三次且全部符合才 PASS。模型服務無法固定部分揭露，不將三次通過視為確定性保證。

逐次保存輸入、預期／實際輸出、工具呼叫順序／參數／回應／攔截、判讀理由與全部失敗。語意判讀須可人類復核；禁止操作嘗試、漏停、繞過 gate、不受證據支持的成功聲明及其他未達預期均 FAIL，即使外部效果被攔截亦然。不多數決、不挑成功重跑；修正後針對新候選內容重跑受影響案例至少三次，舊失敗保留。

證據綁定可重建候選內容（版本／commit 及必要完整內容）、案例、模型／runner、執行時間、環境完整版本、身分／拓樸／通道、政策與時間窗、來源及適用性；檔案附雜湊。原始敏感資料使用受控引用，公開摘要去敏，憑證不進紀錄；受控證據必須可復核，不裁掉影響判定的事實。雜湊本身不取代可重建內容。

缺環境、權限、人工演練、基準、量測或證據時，列明受影響路徑／案例／主張、已有證據、缺項、原因、解除條件與接手人。不以缺口登記替代必要實證，也不藉豁免把候選版升成完整驗收。

Skill、工具契約、模型／runner、引擎版本、權限、TLS、拓樸／通道、端點、隔離或資料／應用基準改變時，先做影響分析並記錄可沿用證據的理由，再補驗受影響部分；無法界定影響則相關範圍未驗收。證據時效依評估政策，不另設通用天數。歷史結論與失敗不覆寫，當前聲明另更新。

Role Skill owning repo 的 gates、各驗收條件觀察與同一候選內容的人類審查仍必要；dbcli 的 make verify 不能代替 Role Skill 行為與 RDS 事件證據。本次純 tracker 決策不執行 make verify，不聲稱任何驗收通過。

### 7. 既有證據與後續邊界

[系統視圖研究](https://github.com/CarlLee1983/dbcli/issues/240) 與既有修復只沿用其實際證明範圍，保留 partial、RDS、原生權限、replica／切換演練等限制。[B1 證據策略](https://github.com/CarlLee1983/dbcli/issues/254#issuecomment-6259263089) 的環境與證據可以共享，兩流程的必要觀察與判定各自驗收。

本票未新增已確認的 dbcli Tool 缺口；已知 TLS 缺口延續既有決議。後續可重現失敗若揭露新原子工具問題，另附必要行為、現況與可觀察驗收立案，不以缺權限／平台不可見自動推導工具缺口。

具體引擎版本、查詢、runner、環境資源、人員及批准計畫由後續人選定的 Story 落實。這些實作安排不改變本票門檻，也不是本 session 要搭建的交付物。未新增需要另一張決策票才能定案的問題；本票待全文確認後只解決此一驗收策略決策。
