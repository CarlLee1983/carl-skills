## B1 最終確認稿（待使用者確認，尚非 Resolution）

本稿彙整本票已確認的七項決策，並補齊最低證據、批准點與 B4 行為驗收。只核准 B1 規格，不授權實作、建立資源或執行演練；不代表地圖或 DBA Role Skill 已完成。

### 1. 評估入口與輸入

開始前選定「備份健康／PITR 目標覆蓋／一次還原演練」中的一項或多項，固定必要主張、最低證據與適用條件。未選項標「本次未評估」，不得因缺證據自行縮小範圍。

記錄評估對象與可追溯資源識別、環境、引擎與版本、部署形態、參考時間與時區、指定備份／PITR 目標，以及新演練或指定歷史演練。專案指定的資料／服務負責人確認 RPO、RTO、備份新鮮度、保留要求、證據時效與量測起訖；資料／應用負責人確認關鍵資料、業務不變條件與對應截點的基準。另列有權批准者、人工執行者與證據交回責任人。

不提供通用預設達標數字。缺政策或基準時，保存可判讀觀察與量測，但不足以判定的相關必要主張為 indeterminate；缺少某項輸入不自動否定其他已有充分證據的主張。

### 2. 必要主張與最低證據

| 主張 | 最低證據與判定邊界 |
| --- | --- |
| 備份存在 | 綁定對象的備份識別、種類、時間及完成／可用狀態。僅有備份設定不足。 |
| 備份符合新鮮度／保留要求 | 已確認要求、可比較的參考時間，以及相關備份時間／實際保留範圍。設定保留天數不自動證明實際涵蓋範圍。新鮮度與保留要求分別判定。 |
| 平台宣告的 PITR 目標覆蓋 | 明確的目標時間點或區間、同一資源的可還原窗口、取得時間與適用性。目標須完整落在窗口內；此主張不等於實際可還原。 |
| 指定演練驗證可還原 | 來源備份／截點、隔離目標識別、人工操作紀錄、還原結果及事先確認的必要唯讀驗證。平台 available、連線成功或口頭完成不足。 |
| 指定演練符合 RPO | 政策目標、事件／演練參考時間、可證實的資料復原點或足以判斷的界限、基準與計算依據。無法將界限判定為達標或超標時為 indeterminate。平台窗口差距與實際資料復原點分開，不用 max(updated_at) 或通用筆數比對冒充已證實的復原點。 |
| 指定演練符合 RTO | 政策定義的起訖、時間戳及終點要求的驗證證據。保留還原作業耗時、必要驗證完成耗時與等待區段；未涵蓋應用恢復時不宣稱服務 RTO 達標。 |

「備份健康」是必要主張的摘要，不新增單一成功狀態。RPO／RTO 與可還原主張分別判定，禁止由平台成功直接推導。證據依 ADR-0046 保存來源、時間、對象、可追溯引用及可取得的來源 ID；檔案附雜湊，敏感原始資料使用受控引用。

### 3. 前置檢查、結果與停止條件

沿用 ADR-0045 的 capability contract 前置檢查：不支援的 schemaVersion 停止整個工作流程；必要 capability 非 available 則停止受影響步驟，不得以「獨立蒐證」繞過版本停止規則。availability 不是執行批准。

沿用 ADR-0046 判定順序：先判充分且無相關矛盾證據支持的 met／not-met；否則相關證據矛盾為 indeterminate，再判必要步驟受阻的 blocked，其餘不足為 indeterminate。缺 AWS CLI／唯讀 IAM 明確為 indeterminate；等待人工批准／執行或必要 capability 不可用依既定規則為 blocked。不得用輔助查詢受阻掩蓋已有充分證據的 not-met。

PITR 目標在完整、適用且無相關矛盾的窗口外為 not-met；窗口不足、過時或矛盾為 indeterminate，不自動改目標。目標身分不明則停止對該目標查詢；隔離未確認則停止還原交接。其餘安全且獨立的唯讀評估可繼續。

沿用「dbcli query-only 是否放行 RDS 的唯讀程序」的決議：CALL 拒絕所致的無法取得觀察為 indeterminate，交既有授權人員取證，不升權、不自動換 AWS API 或原生客戶端；binlog retention hours 不等於 BackupRetentionPeriod。此限制不禁止原本已列入計畫的 RDS 平台唯讀觀察。

### 4. 演練與清除交接

建立、還原、設定及清除均由人執行，包含非正式環境。Role Skill 準備 runbook、蒐證與唯讀驗證。B1 v1 不包含正式流量切換、建立持續存取或持續演練排程。

執行前確認來源／目標身分、隔離措施（包含避免誤接正式流量及不預期外連）、資料與連線存取限制、唯讀驗證範圍與執行預算。runbook 列明人工執行者、影響、費用與敏感資料風險、安全停止方式、回復限制、時間窗、重試限制及證據交回方式。

批准點位於人工變更前及人工清除前。清除可由同一份有效批准涵蓋，無須重複取得同一授權，但執行前仍核對批准有效、目標、刪除範圍及必要證據已保留。實質變更須重新批准。批准資格、來源與撤回依 ADR-0047。

撤回或停止不等於回滾；已開始操作交人依預定安全停止方式處理。清除失敗記錄殘留資源、原因、負責人及後續交接，不能宣稱已收尾；也不因此抹去已成立的歷史復原結論。必要證據保存失敗且無合格替代證據，對應主張為 indeterminate。

### 5. 歷史演練與適用性

可選定已完成且可追溯的歷史演練評估，不強制重新還原。結論限定當次來源、截點、環境與驗證條件，另列證據目前是否可取得、符合本次用途的時效，以及引擎、金鑰、設定、資料範圍變動的適用性缺口。不覆寫歷史，也不把歷史成功升格為目前可還原。

### 6. B4 行為驗收矩陣

| 情境 | 預期行為 |
| --- | --- |
| 所選主張必要證據齊全、適用且無矛盾，全部符合 | 僅宣稱本次固定範圍內全部符合，未選項仍為本次未評估。 |
| 備份存在但新鮮度／保留不符 | 分別記錄 met／not-met，保留混合結果。 |
| PITR 目標在窗口內、外、邊界或窗口缺失／過時 | 依來源窗口邊界語意及政策判定覆蓋；完整適用證據顯示在外為 not-met，缺證據為 indeterminate，不改目標、不宣稱已演練。 |
| 平台成功，但資料驗證失敗、不足或矛盾 | 對受影響主張依證據分別判定，不由平台成功推導可還原或 RPO／RTO 達標；充分失敗證據與不足證據分開。 |
| 缺政策、基準或量測起訖不相容 | 保存可判讀量測；不足以判定的主張為 indeterminate。 |
| 目標不明、隔離未確認、批准拒絕／過期／撤回 | 停止受影響查詢或執行交接，指明解除條件與接手人；不假設已開始操作被回滾。 |
| capability 非 available／版本不支援 | 前者阻擋必要步驟，後者停止整個流程；不繞過 gate。 |
| CALL 拒絕／IAM 缺失／原生查詢無權或查詢失敗 | 不冒充物件不存在或備份不健康，不升權或自動替代執行；按已定政策與證據規則記錄。 |
| 歷史演練成功但目前環境改變 | 保留歷史結論並揭露目前適用性缺口。 |
| 清除失敗／必要證據保存失敗 | 明示未收尾與接手人／對應證據缺口；不因命令成功隱藏問題。 |
| 自管環境只有引擎層訊號 | v1 未涵蓋的平台層為 indeterminate；WAL／binlog 訊號不證明完整備份鏈或實際可還原。 |

此表是規格驗收要求，不代表已測試。如何建立隔離環境、故障注入或使用 fixture，仍由地圖既有 B4 測試環境議題後續收斂。

### 7. Tool 缺口與後續交付邊界

僅將已有證據證明「必要而 dbcli 缺少的原子能力」列為 Tool 候選缺口；不把 IAM、原生權限、平台可見性、人工證據或業務基準缺失改寫成 dbcli 功能需求。CALL 拒絕是已定政策。本輪未確認新增 Tool 缺口，不宣稱所有能力均已驗證；既有研究的 partial、RDS、最小權限、replica／還原演練限制保留。

後續規格與 Story 必須把各引擎的必要操作對應到已存在的 capability ID、contract 版本與實際證據取得方式；不能虛構 ID 或以本票替代實測。若這項對應暴露新的原子缺口，另立決策／Story，不能默默擴充本票。
