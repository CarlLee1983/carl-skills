## B1 驗收證據與測試環境策略 — 最終確認稿（待使用者確認，尚非 Resolution）

本稿彙整本次 wayfinder 訪談 Q1–Q7 已確認的決策，具體化 [B1 備份與復原工作流程規格](https://github.com/CarlLee1983/dbcli/issues/251#issuecomment-6258749706) 的驗收證據要求。B1 的必要主張、判定優先序、安全停止、人工批准與交接均沿用已核准規格，不由本票改寫。

本票只決定未來驗收策略，不代表 Skill 已實作、測試已通過或環境已具備；不授權建立資源、設定帳號、執行演練、清除資源或發布產品。B2／B3 由各自決策票處理。

### 1. 交付門檻與三種不同的結果

採分階段驗收：

- **候選版**：全部必要行為案例通過後，可標示「B1 行為驗收通過，實環境驗收未完成」，連結逐項缺口。若行為案例尚未全部通過，只能報告實作／驗證進度，不能使用此聲明。
- **完整 B1 驗收**：行為驗收、下列六組環境與各 RDS 還原路徑的必要實證、可追溯證據及對同一候選內容的人類驗收審查均完成，才可宣稱指定範圍完整驗收。若僅部分環境完成，可逐項陳述已驗收事實，但整體仍為候選版。
- **發布授權**：與上述驗收分開；本決策不授權發布任何版本。

三個維度分開記錄，不互相轉換：

1. 行為測試的 PASS／FAIL（未執行不得算 PASS）。
2. 單一 DBA 主張的 met／not-met／blocked／indeterminate，沿用 B1 與 ADR-0046。
3. 哪些平台、引擎、版本、部署形態與操作路徑已有適用的實環境證據，哪些尚未驗收。

正確判出 not-met、blocked 或 indeterminate 可以讓對應行為測試 PASS，不能證明資料庫主張 met。完整 B1 驗收證明工作流程依契約正確運作，不承諾每個受評資料庫都達成 RPO／RTO。

### 2. 最低平台、引擎與版本覆蓋

| 引擎 | 自管環境 | AWS RDS |
| --- | --- | --- |
| PostgreSQL | 一組固定版本的隔離引擎層實證 | 一組固定版本的真實 RDS 取證與還原實證 |
| MySQL | 一組固定版本的隔離引擎層實證 | 一組固定版本的真實 RDS 取證與還原實證 |
| MariaDB | 一組固定版本的隔離引擎層實證 | 一組固定版本的真實 RDS 取證與還原實證 |

自管可用隔離本機／容器環境；它驗證實際 SQL 取證及受限權限行為，不證明自管平台層的備份鏈或可還原性。自管平台層維持 v1 不涵蓋、indeterminate 並交接給人。Aurora、其他代管平台及生產流量切換不在本票範圍。

每組在實作 Story 開始時依當時可用且計畫支援的 RDS 版本，選定並記錄完整引擎版本及自管對照版本；自管與 RDS 不假設可取得完全相同的 patch。另固定部署形態、區域、相關設定、dbcli／AWS CLI 版本、capability contract 版本與實際帳號權限。對支援與實證的聲明只能涵蓋已驗收組合，不由單一 patch 推導其他版本或部署形態通過。若未來增加組合，另補對應證據。

六組是最低覆蓋，不等於六個必須同時存在的環境，也不等於只需六次工具呼叫。環境可以分時建立；任何建立、設定、還原及清除仍由人依批准計畫執行。

### 3. 三類證據與實環境最低要求

**F：可重跑的合成案例／fixture**。驗證真正 Role Skill 的判定、工具選擇、停止、交接與結果呈現；所有合成來源及時間／政策／資料基準明確標示。工具回應由受控測試替身提供，外部效果在測試邊界攔截；仍完整記錄 Skill 曾嘗試的呼叫。被攔截的禁止操作嘗試同樣判 FAIL，不能因「沒有真的執行」當成安全通過。

**L：隔離自管引擎實證**。各引擎使用實際預定的受限帳號，經 dbcli 完成 B1 適用的必要唯讀取證與驗證查詢，記錄查詢範圍及可見性限制；保留安全的權限不足案例。環境本身沒有的平台訊號不能靠 fixture 補成真實證據。

**R：真實 RDS 及人工演練實證**。各引擎取得原計畫內的 RDS 平台唯讀觀察、dbcli 引擎層必要取證、所用權限與可見性限制，並保留安全的權限不足案例。每個 RDS 引擎分別具備至少一次**快照還原**及一次 **PITR** 的成功還原與必要資料驗證證據；每份證據限於其實際路徑與環境組合，不能代替另一條路徑。

R 的兩條演練路徑都需要：

- 來源備份／截點與來源資源、隔離目標身分及隔離檢查。
- 綁定計畫版本的有效批准、人工操作與完成紀錄。
- 事先確認的必要資料／業務基準及 dbcli 唯讀驗證證據；available、連線成功或口頭完成不足。
- RPO／RTO 的政策、起訖、可判讀且足以判定的量測與計算依據。超標可正確判 not-met，不強迫業務目標達標；量測不足仍保留相關驗收缺口。未驗應用恢復不得宣稱服務 RTO。
- 清除的批准核對、人工執行及收尾紀錄；失敗要有殘留資源、原因、責任人與後續交接，不能宣稱已收尾，也不能抹去既有歷史復原結論。

符合 B1 的可追溯歷史演練可抵用相應部分；必須逐項檢查來源、截點、版本、設定、資料基準、權限及目前用途的適用性，不能因為「以前成功」免除當前候選 Skill 行為驗收或其他必要實證。

安全的真實權限不足案例使用人員事先準備／批准的受限身分或適用的既有紀錄，只執行原定範圍內的唯讀操作。agent 不自行撤權、升權或改帳號。RDS 平台 IAM 與引擎原生權限的觀察分開，不能互證。高權限帳號成功不能代替預定受限帳號驗收；受限帳號成功也不構成「最小原生權限已證明」的聲明。

不要求在實環境故意製造損毀、危險隔離、撤回中的資源操作或清除失敗；這類失敗分支使用 F。F、L、R 的證明範圍不能互相冒充。

### 4. 十一類 B4 情境的證據對照

每列及其列出的必要分支都需要 F；L／R 欄說明完整實環境驗收還需要哪些事實。不是把一個類別當作一個案例；分支依 B1 判定與安全邊界展開。

| B1 情境 | F 必須驗證的行為與分支 | L／R 的必要實證或限制 |
| --- | --- | --- |
| 1. 所選主張證據齊全且全部符合 | 僅宣稱固定範圍內符合；未選項仍為本次未評估；不得自行縮小範圍 | R 取得真實備份、窗口與兩條人工演練證據；每項主張按實測判定，不強迫所有政策目標達標 |
| 2. 備份存在但新鮮度／保留不符 | 新鮮度與保留分開測；保留 met／not-met 混合結果；設定值不當成實際覆蓋 | R 記錄真實備份身分、完成狀態、時間及實際保留範圍；不用故意讓真實備份過期 |
| 3. PITR 目標在窗口內、外、邊界，或窗口缺失／過時 | 內、外及各邊界依來源語意；缺失、過時、矛盾分支；不改目標、不宣稱已演練 | R 留存真實窗口、來源時間及目標比對，另有 PITR 人工演練；合成邊界案例不冒充 AWS 實測 |
| 4. 平台成功但資料驗證失敗、不足或矛盾 | 三種分支分開；充分失敗證據與不足證據不混用；可還原、RPO、RTO 分別判定 | L 驗證唯讀查詢；R 取得平台、人工操作、基準與實際資料驗證的完整鏈；資料不一致可用 F 注入 |
| 5. 缺政策、基準或量測起訖不相容 | 分開覆蓋缺項與不可比量測；保存可判讀觀察，受影響主張 indeterminate | R 的合格演練必須有適用政策、基準與可判定的 RPO／RTO 量測；缺少就保留缺口 |
| 6. 目標不明、隔離未確認、批准拒絕／過期／撤回 | 各停止點、解除條件、接手人；已開始操作不假設回滾；安全獨立評估能否繼續依 B1 | R 提供真實身分、隔離、批准與人工交接；危險與撤回分支用 F，不要求真實誤接或破壞 |
| 7. capability 非 available／版本不支援 | unavailable、unknown、無法解析必要設定等非 available 情況；步驟阻擋與整體版本停止分開；無替代繞過 | L／R 留存實際前置檢查及版本；不支援版本與無法取得環境的分支可由 F 驗證 |
| 8. CALL 拒絕／IAM 缺失／原生無權或查詢失敗 | 分開覆蓋各原因；沿用判定優先序；不宣稱物件不存在或備份不健康，不升權、不自動換工具 | L／R 各保留受限帳號正常取證與安全權限不足案例；R 分別記錄平台與引擎權限限制；CALL 政策拒絕不證明 RDS 程序可用性 |
| 9. 歷史成功但目前環境改變 | 歷史不覆寫；目前適用性與缺口另列；不自動提升為目前可還原 | 採歷史 R 證據時逐項審查適用性；僅本機歷史資料不能替代 RDS 演練 |
| 10. 清除失敗／必要證據保存失敗 | 分開測殘留資源交接與證據缺口；無合格替代證據時依 B1 為 indeterminate；不隱藏未收尾 | R 保存實際清除／交接結果及證據可取得性；錯誤可用 F 注入，清除失敗不抹去既有主張，但未收尾不得當成完整收尾 |
| 11. 自管只有引擎層訊號 | 平台層 indeterminate；WAL／binlog 不等於完整備份鏈或可還原 | 三組 L 實測引擎取證及流程輸出，自管平台層仍不在 v1 驗收範圍 |

共同交叉案例須覆蓋：有充分 not-met 證據但輔助查詢受阻、證據矛盾與受阻並存、必要證據保存失敗有／無合格替代、混合主張結果。預期輸出依 B1／ADR-0046 原有優先序，不另創狀態規則。

### 5. 重跑、判讀與證據留存

每個必要 F 案例固定 Skill 內容、fixture 與 oracle（預期行為）、工具契約、模型識別與可控制的設定、runner 版本；以全新 session **至少三次，全部符合才 PASS**。模型服務無法固定的部分須揭露，不把三次通過宣稱為確定性保證。

驗證對象是實際 Role Skill 的執行，不只是旁邊的狀態判斷函式，也不能由人工閱讀示例代替。逐次保存輸入、預期與實際輸出、工具呼叫順序與參數、工具回應及攔截紀錄、判讀理由。語意判讀須可被人復核，不以逐字一致代替正確行為。

禁止操作嘗試、漏停、繞過 gate 或不受證據支持的成功宣稱均 FAIL；其他未達案例預期也 FAIL。不得多數決、只保留成功重跑、或以 runner 攔截成功掩蓋 Skill 的錯誤意圖。修正後對新候選內容重新執行受影響案例至少三次；原失敗紀錄仍保存。

證據綁定可重建的候選內容（版本／commit 及必要的完整內容）、案例版本、執行時間、環境與版本、證據來源／身分、適用性、結果、缺口與責任人。原始敏感資料及憑證不得貼入公開 issue；憑證不留入測試紀錄，敏感原始資料採受控引用。公開摘要須去敏，受控證據須足以復核而不裁掉影響判定的事實；檔案以雜湊標識。

B1 實作的 repository gates、每個驗收條件的觀察及精確候選內容的人類審查仍須依其 owning repo 規範完成；dbcli 的 `make verify` 通過本身不能代替 Role Skill 行為與 RDS 演練證據。

### 6. 缺口與證據更新

缺少環境、唯讀授權、人工演練、基準或可取得的證據時，逐項記錄：受影響環境／路徑／案例／主張、已有證據、缺少什麼、限制原因、解除條件與接手人。不得把未執行當 PASS，也不得用擬議豁免把候選版升為完整驗收。缺口標示不是新增 DBA 主張結果，實際主張仍按既有四種狀態判定。

Skill 判定邏輯、工具契約、模型或 runner、引擎版本、權限、金鑰、資料基準或隔離設定改變時，先記錄影響分析與可沿用證據的理由，再補驗受影響部分。無法界定影響時，相關範圍維持未驗收，不任意沿用通過。證據時效依每次評估已核准政策，不新增通用天數。

歷史結論與失敗紀錄不覆寫；當前驗收聲明另更新。後來失效不抹去過去觀察，也不讓過去觀察繼續自動支持現在。

### 7. 既有研究與後續邊界

[dbcli 能否讀取 DBA 工作流程所需的系統視圖](https://github.com/CarlLee1983/dbcli/issues/240) 的本機研究包含 PostgreSQL 16.11、MySQL 8.4.8、MariaDB 11.8.8 的 SQL probe，屬 partial 研究；未涵蓋 RDS、實際 PITR／還原演練及完整最小原生權限證明。既有修復／測試只能引用其實際證明的範圍，不整批移作本票驗收完成證據。

[備份與 PITR 的可觀察訊號與原生工具](https://github.com/CarlLee1983/dbcli/issues/237) 的未驗證 RDS 行為與原生權限限制繼續保留。[dbcli query-only 是否放行 RDS 的唯讀程序](https://github.com/CarlLee1983/dbcli/issues/241#issuecomment-6258605053) 的 CALL 拒絕政策不變。

本票未確認新增 dbcli Tool 缺口。操作／capability 對照與跨工作流程 Tool 缺口仍由 [各工作流程的 capability 需求與 Tool 缺口定案](https://github.com/CarlLee1983/dbcli/issues/255) 處理。具體引擎版本、測試 runner、環境資源與人員安排由後續人選定的實作 Story 落實本策略，不在本票搭建或執行。
