## B3 最終確認稿（待使用者確認，尚非 Resolution）

本稿彙整兩輪已確認的八項決策，補齊最低證據、停止條件、批准交接與 B4 行為驗收。核准對象是 B3 規格，不是實作、變更帳號權限或執行生產變更的授權，也不代表任何情境已通過實測。

### 1. 評估入口、輸入與責任

每次開始前，從「原生權限符合基準」「TLS／憑證符合要求」「指定變更的執行前準備」「指定變更的執行後驗證」選一項或多項，事先固定必要主張、對象、環境、時間、適用條件與最低證據。未選項標「本次未評估」，不能事後移除失敗或缺證據的必要主張。就緒度、批准有效性及執行結果分開記錄；稽核通過不證明變更安全。

輸入記錄資源／連線及資料庫身分、引擎與確切版本、適用的儲存引擎、部署形態、評估帳號／角色／物件／客戶端範圍、取得時間與時區。變更另記計畫版本、目的、精確目標、操作及順序、預期差異、受影響依賴與指定事件；區分新觀察和歷史證據。

專案指定的資料／服務負責人及安全責任人確認期望權限與 TLS 基準：帳號用途、允許物件／操作、角色繼承與管理權限、例外及有效期限、TLS／憑證要求、證據範圍與時效。變更負責人確認鎖等待、操作／影響時間、查詢負載與觀察預算、停止門檻、復原要求及驗證基準；資料／應用負責人確認必要業務不變條件與服務恢復標準。另列有權批准者、人工執行者及證據交回責任人。

Role Skill 可提出建議，不自行套用通用達標秒數或把現況當基準。缺基準仍可盤點；無法比較的相關主張為 indeterminate，不抹去其他已充分證成的結論。

### 2. 範圍與操作邊界

引擎層涵蓋 PostgreSQL、MySQL、MariaDB 的自管與 AWS RDS 環境，由 dbcli 執行計畫內唯讀觀察。平台層只涵蓋 RDS，不含 Aurora；自管及其他平台未涵蓋的平台層主張為 indeterminate 並交人，不因此否定可評估的引擎層主張。

變更治理涵蓋原生 DDL、原生帳號／角色／GRANT，以及 TLS／憑證相關變更；三類各有對應的前置、復原與驗證交接。大量 DML／資料回填、應用發布、通用主機維運及自管平台層操作不納入 v1。需要應用或客戶端配合時，記錄相依工作、責任與交回證據，不擴張成應用發布或客戶端部署工具。

Role Skill 準備 runbook、蒐證、判讀與唯讀驗證；變更、設定、重啟、終止連線／blocker、復原及清理均由人執行，不因非正式環境而自動授權。新增驗收演練在隔離環境由人執行，不為測試在正式環境製造長鎖、高負載、憑證錯誤或權限故障；本票不搭建環境。

v1 完整規格化原生操作。需要 gh-ost、pt-online-schema-change 等外部工具時，記錄適用性、限制與待補條件，交專家；不默認替換工具，不將完整外部工具 runbook 納入 v1，也不把外部工具缺口當作已具備執行條件。

### 3. 稽核主張與最低證據

以下按實際引擎、版本及部署形態採適用項目。每項證據連結同一評估對象、時間、來源與可見範圍；不能將不同帳號、客戶端或時間的結果拼成不存在的完整快照。

| 主張 | 最低證據與判定界線 |
| --- | --- |
| 指定帳號／角色的權限符合基準 | 已確認的用途與預期權限、完整的目標識別及適用的直接授權、角色成員／繼承／啟用關係、PUBLIC、擁有者、管理／再授權能力與預設權限。分清目前物件、未來物件與本次 session 的有效權限，不僅比較直接 GRANT。 |
| 高權限與例外符合要求 | 適用的高權屬性、全域／動態權限或受管角色、影響範圍，以及例外批准、用途與期限。RDS 受管角色按實際能力判讀，不把角色名稱視為通用 superuser。 |
| 指定連線的 TLS 符合要求 | 同一連線／端點、時間、傳輸方式、適用的 TLS 協定與密碼套件等訊號，以及政策要求。僅支持該連線或明確觀察窗內的指定集合，不推導所有連線均符合。 |
| 伺服器／帳號的 TLS 強制政策符合要求 | 適用的生效設定、帳號要求或存取規則與覆蓋範圍；RDS 平台設定須區分要求值、套用狀態與實際生效證據。支援 TLS 或目前使用 TLS，不等於拒絕非 TLS。 |
| 指定客戶端的憑證與主機名驗證符合要求 | 該客戶端／驅動及版本的有效驗證設定、信任來源與對應連線證據。資料庫端加密訊號不能單獨證明客戶端驗證了伺服器身分；缺客戶端證據為 indeterminate。 |
| RDS 憑證狀態符合要求 | 同一資源的伺服器憑證／CA 識別、適用的有效期限、輪替與套用狀態，以及政策時點。CA 有效、伺服器憑證有效與客戶端信任分開判讀，不以其中一項代替其餘。 |

最小權限是相對於經確認的用途與必要操作，不以「權限越少越合格」或通用清單替代需求。複雜權限語意超出可證明範圍時列明缺口，不能自稱完整有效權限分析器。

可見性不足時，保留安全且獨立的唯讀盤點，列出可見／不可見對象、欄位、時間及所需證據，交既有授權者補證。空集合、NULL、查詢失敗、無權、blacklist 省略均不自動證明不存在或符合；只看得到自己不代表全體。不得自行升權、改 profile、安裝 extension、取消 blacklist，或繞到原生客戶端。

蒐證只選必要欄位，避免讀取或保存密碼雜湊、認證字串、私鑰與其他非必要秘密。敏感原始資料使用受控引用；不將帳號稽核資料直接貼入公開 issue。

### 4. 變更前準備、預算與復原

就緒度表示指定計畫在指定時點具備所要求的前置證據，不保證稍後執行安全。runbook 必須列出：

- 目標、版本與操作適用性、具體操作順序、預期差異、依賴、影響及責任人。
- 適用的交易邊界、implicit commit、鎖取得／持有風險、演算法限制、資料重寫、額外空間與複製影響；不以 online／concurrent 名稱推導無鎖或無影響。
- 經負責人確認的鎖等待、操作與影響時間、負載／容量及複製健康門檻，觀察與停止方式，以及誰執行停止；各預算獨立，查詢逾時不冒充 DDL 的伺服器端鎖等待控制。
- 前置證據的時效與人工接手時必須重查的條件。長交易／blocker、高負載、空間不足、來源矛盾或版本不符不能被舊快照掩蓋。
- 復原方案、適用前提、預估影響、負責人、批准範圍、事後驗證及殘留處置。

DDL 的 rollback 能力逐項按版本／操作判定。區分未提交交易的回滾、已提交變更的補償修正、備份復原與不可逆性；atomic DDL 不等於使用者可回滾。失敗、逾時或連線中斷不表示未產生變更，重試前先確認實際狀態，不能盲目重跑。

權限變更須確認受影響帳號、應用與管理存取、既有／新連線的生效條件，以及避免管理者與驗證者被鎖出的交接；不得由 agent 建立備援帳號或持續存取。TLS／憑證變更另確認客戶端信任配合、生效／重啟條件與重連驗證。資料庫端設定成功不替代客戶端可用性。

每項變更應有可行復原方案。若確實不可復原，須由有權者明確接受該計畫的風險並確認停止／善後方式，且不得豁免專案強制復原要求。只有「備份存在」不足以證明可復原本次變更；可引用 B1 合格且適用的復原證據，不強制重演，也不假定整庫還原能無損保留變更後的寫入。

缺必要預算、前置證據、驗證基準或合格復原／風險處置時，可保留待補 runbook，但不得標為已具備執行條件。任何自動降級演算法、延長等待、換工具、升權、終止其他連線或擴大重試皆不允許；必要改案須重新確認條件與批准。

### 5. 批准、執行交接與執行後驗證

沿用 ADR-0047。批准綁定確切計畫版本、環境、資源、操作、本次時間窗與允許重試；確認批准資格與來源。批准點位於人工變更、復原與清理前，單一有效批准可明確涵蓋多個步驟，無須重複索取同一授權；每步仍核對目標、前置條件及批准適用性。

接手人重新確認證據時效、門檻、停止／復原責任及驗證計畫。批准不自動觸發操作；工作流程批准、dbcli 執行 gate、技術結果互不替代。超範圍、過期、撤回、資格未確認或條件實質改變時，停止未開始的相關交接；已開始操作由人依安全停止計畫處理，撤回不等於回滾。

執行後交回計畫／事件識別、實際目標與操作、成功／失敗／部分完成／狀態未知的紀錄、起訖及等待時間、停止／重試、前後觀察、驗證結果與殘留情況。必要項目在執行前按操作固定：

| 變更類型 | 執行後必要驗證邊界 |
| --- | --- |
| DDL | 實際 schema 差異及物件有效性、適用的約束／索引與資料不變條件、應用相容性、負載／複製健康及殘留物件。不能只由命令成功或表存在判定完成。 |
| 帳號／角色／GRANT | 預期授予與撤銷的實際效果、有效角色與權限、必要的允許／拒絕存取及應用／管理存取。按版本與帳號確認既有／新連線的生效條件，不因一個 GRANT 成功推導整批符合。 |
| TLS／憑證 | 生效設定及憑證、指定客戶端的信任／主機名驗證與重連、政策要求的非合規連線拒絕，以及必要的應用可用性。不能由舊連線仍正常推導輪替成功。 |

上述是依操作選定的必要子主張，不是每次強制執行所有探測。任何可能寫入、使用額外身分、改變連線政策或造成負載的驗證，須明列在批准計畫，由指定人工執行者處理；不得為證明拒絕而以 agent 試做未授權寫入。非必要或不適用項目事先記理由，不能事後刪除失敗項目。

技術結果、批准合規及收尾分開。操作成功但沒有批准證據，不能補稱已獲准；執行後缺資料／應用等必要證據時，對應主張不能判 met。清理／復原失敗列殘留、原因、接手人及解除條件，不宣稱已收尾，也不覆寫已有的歷史技術結論。

### 6. 結果、停止條件與歷史適用性

沿用 ADR-0045：必要 capability 與 contract 版本先檢查；不支援的 schemaVersion 停止整個工作流程，必要 capability 非 available 停止受影響步驟。不得以獨立蒐證繞過版本停止規則；availability 不是批准。

沿用 ADR-0046 判定順序：充分且無相關矛盾的證據先判 met／not-met；否則未解決的相關矛盾為 indeterminate，再判必要步驟受阻為 blocked，其餘不足為 indeterminate。必要 capability 不可用、等待人工批准或執行，分別記原因及交接；缺 AWS CLI／唯讀 IAM 為 indeterminate。輔助查詢受阻不掩蓋已充分證實的過度授權或其他 not-met。

CALL 拒絕所致的觀察缺口沿用既定政策，記為 indeterminate 並交既有授權人員取證，不升權、不自動換 AWS API 或原生客戶端；不禁止原本已列入計畫的 RDS 唯讀 API。原生權限、平台可見性、基準及人工證據缺口不自動變成 Tool 缺口。

目標身分不明時停止對該目標查詢；觀察達負載／逾時預算則停止該觀察；前置條件不足、批准失效或操作超界時停止受影響交接。其餘安全且獨立的唯讀評估可繼續，但不能縮小範圍或改門檻以求通過。流程可產出完整的評估紀錄並保留混合結果；只有所有事先選定的必要主張均為 met，才宣稱本次固定範圍內全部符合。

證據保存來源、取得時間、對象／環境、可追溯引用及可取得的來源 ID；檔案附內容雜湊，雜湊不證明真實性或批准。必要證據保存失敗且無合格替代時，相關主張為 indeterminate。

可評估可追溯的歷史變更，不強制重演。結論限定當次版本、操作、基準、身分、環境與驗證條件；另列目前政策、帳號、schema、憑證、客戶端或部署變動造成的適用性缺口。新的評估不覆寫舊結論，歷史成功不升格為目前符合，也不偽造當時未取得的批准。

### 7. B4 行為驗收矩陣

| 情境 | 預期行為 |
| --- | --- |
| 1. 所選必要主張證據齊全、適用且無矛盾 | 僅宣稱本次固定範圍內全部符合；未選項仍為本次未評估，就緒不等於已執行。 |
| 2. 缺權限／TLS 基準、例外過期或基準不適用 | 無法比較者為 indeterminate；有充分證據違反有效政策者為 not-met，不把現況當期望。 |
| 3. 直接 GRANT 看似正常，但繼承、PUBLIC、owner、高權或預設權限不同 | 按各引擎的有效語意及基準判定，揭露可達權限與未來物件差異；不宣稱直接授權清單完整。 |
| 4. 只看見自身、NULL／空集合、無權、blacklist 省略或查詢失敗 | 保留觀察與可見性缺口，不判全體符合／對象不存在，不升權或收集非必要秘密。 |
| 5. 已證實過度授權，但輔助查詢受阻 | 保留 not-met 及缺口，不把整體壓成 blocked。 |
| 6. 本連線已加密，但未證實強制 TLS、客戶端驗證或其他連線 | 分項判定；缺必要證據者 indeterminate，已充分證實違反要求者 not-met。 |
| 7. RDS 要求值、pending apply、引擎生效值或憑證證據不同 | 分清設定階段與證據語意，未解決相關矛盾為 indeterminate；不把期望值當已生效。 |
| 8. 長交易／鎖等待、高負載、空間不足或複製門檻超標 | 停止受影響交接，或交人按計畫停止已開始操作；不自動 kill、延長預算或改門檻。 |
| 9. 版本／操作不適用、ALGORITHM／LOCK 要求無法滿足或需要外部 OSC | 不靜默降級或換工具；保留待補條件並交人／專家，不報已具備執行條件。 |
| 10. DDL 失敗、逾時或斷線，但部分操作已提交／結果未知 | 先重查實際狀態，不宣稱整批 rollback、不盲目重試；區分 implicit commit 與可回滾性。 |
| 11. PG concurrent index 失敗後留有 INVALID 索引或其他殘留 | 不把失敗當未變更；記錄有效性、影響與人工清理批准。 |
| 12. 無通用 rollback、只有備份存在或不可復原風險未接受 | 不報具備執行條件；要求適用復原證據或政策允許且有效的風險接受，不能豁免強制要求。 |
| 13. 權限變更造成應用／管理存取失敗，或既有／新連線效果不同 | 分開判定授權效果與存取驗證，揭露部分生效；交人處理，不自建帳號或繞過權限。 |
| 14. TLS／憑證已更新，但客戶端不信任、重連失敗或仍接受政策禁止的連線 | 分項判定，不由設定成功或舊連線正常宣稱輪替完成。 |
| 15. 批准拒絕／過期／撤回／資格不明、計畫改變或超範圍重試 | 停止未開始步驟；已開始操作交人依計畫處理，停止不等於回滾。 |
| 16. 命令成功，但 schema／資料／應用／複製驗證失敗或不足 | 各必要主張分別 not-met／indeterminate，保留混合結果，不給單一成功。 |
| 17. capability 非 available、contract 不支援、CALL 拒絕或平台前置條件缺失 | 依既定規則停止、判定及交接；版本不支援停止整個流程，其他受影響範圍分開，不繞過 gate。 |
| 18. 歷史成功但現況改變、必要證據過時／不可得或保存失敗 | 保留歷史及目前適用性缺口；無合格替代證據的本次主張 indeterminate。 |
| 19. 清理／復原失敗，或人工探測需要額外權限／寫入 | 明示未收尾、殘留及接手人；探測須按批准計畫交人，不以驗證之名擴權。 |

這些是規格要求，不表示已測試。fixture、隔離本機、真實 RDS、人工執行及客戶端／應用證據的分工，與引擎／版本覆蓋，待 B3 驗收證據與測試環境決策收斂；不能以 fixture 宣稱真實權限、TLS 或 DDL 生產行為已驗證，也不能以 blocked／indeterminate 當成相應主張通過。

### 8. 技術依據、Tool 缺口與後續交付

沿用 [DDL 引擎差異研究](https://github.com/CarlLee1983/dbcli/issues/235)與[原生權限／TLS 研究](https://github.com/CarlLee1983/dbcli/issues/239)，但研究摘要不能代替逐版本、逐操作的語意與實測：

- MySQL 的 CREATE／DROP TEMPORARY TABLE 不 implicit commit，卻仍不可由使用者 rollback；不能寫成所有 DDL 一律 implicit commit，也不能反向推論未提交即可回滾。MariaDB 必須依自身版本文件核對，不直接移植 MySQL 結果。[MySQL 交易文件](https://dev.mysql.com/doc/refman/8.4/en/implicit-commit.html)
- MySQL SHOW GRANTS 查看其他帳號需要 mysql system schema 的 SELECT，不能當作無該權限時的通用替代；PG 其他 session 部分統計欄位有可見性限制，不能假設 SELECT／SHOW 執行成功即取得完整觀察。[MySQL SHOW GRANTS](https://dev.mysql.com/doc/refman/8.4/en/show-grants.html)、[PG 統計可見性](https://www.postgresql.org/docs/current/monitoring-stats.html)
- PG concurrent index 建立失敗可能留下 INVALID 索引，須驗證殘留；具體清理交人按批准計畫處理。[PG CREATE INDEX](https://www.postgresql.org/docs/current/sql-createindex.html)

本票未確認新增原子 Tool 缺口，不代表所有必要能力已實測。既有研究的 partial、RDS、原生最小權限及版本差異限制保留；各必要觀察對應的實際 capability ID、contract 版本與證據取得方式，由[各工作流程的 capability 需求與 Tool 缺口定案](https://github.com/CarlLee1983/dbcli/issues/255)收斂。只有證據證明必要行為缺少原子工具能力時才列候選缺口，不虛構 ID、不把批准、平台可見性、基準或 CALL 拒絕政策改寫成 dbcli 功能需求。

本票核准後，將 B3 驗收證據與測試環境策略從地圖未指定事項轉為獨立決策票；本 session 不繼續解該票。外部 OSC 完整操作流程、大量 DML／資料回填、應用發布與通用主機維運列為本次範圍外，不放入待發掘事項。具體 Skill、runbook 範本、查詢與 Story 實作屬地圖後續交付，不在本票製作。
