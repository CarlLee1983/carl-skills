# B2 實環境驗收缺口

本表依 [B2 Story](../specs/b2-candidate.md) 與 [#256 核准策略](https://github.com/CarlLee1983/dbcli/issues/256#issuecomment-6259493405) 保留完整 B2 最低門檻。此 Story 只交付本機行為候選，不授權建置、帳號變更、真實取證、故障注入、切換或清除。後續須由人另選 Story、實際版本、資源、批准計畫及接手人；以下「角色」不是已指派的人員。

已有證據限於合成 F：已驗收 B1 基線的可重建來源為本機 `.verification/review-12/source/`，其證據與批准見 `.verification/HANDOFF.md`。B1 PASS 不替代 B2，也不沿用為變更後候選的 PASS。B2 F 執行、判讀與 canonical gate 結果以同一候選的本機 handoff 為準；本表不預先宣稱通過。未提供任何 L／R 實證，合成版本、通道、帳號及平台回應均不算實環境證據。

F 的 PASS／FAIL、DBA 主張的 met／not-met／blocked／indeterminate、L／R 覆蓋與同一候選的人類驗收分開記錄。正確判出失敗或不足可使 F PASS，不能抵銷以下缺口。人類驗收目前 pending；完整 B2 驗收與發布授權另行決定。

## L：隔離自管引擎

下列每列目前均只有合成 F 的行為測試邊界，沒有可抵用的真實環境證據；原因均為本 Story 排除實環境操作。解除條件須由後續批准計畫落實，agent 僅在計畫內唯讀取證。自管只驗引擎層，不升格為平台切換／故障管理驗收。

| 必要路徑／受影響主張 | 缺項 | 解除條件 | 接手角色 |
| --- | --- | --- | --- |
| PostgreSQL primary＋replica，實體串流複製 | 身分／角色／關係、適用進度／lag／錯誤及 WAL 保留風險；正常、lag、複製停止與恢復；活動及無寫入期 | 人員準備隔離基線與受控狀態，取得可追溯樣本及有限觀察窗，按事先政策分項判定 | PostgreSQL DBA／環境負責人 |
| MySQL primary＋replica，原生非同步複製 | 同上各狀態與活動／無寫入期；MySQL 來源語意、進度／lag／錯誤及 binlog 保留風險 | 人員準備基線與狀態，保留實際 MySQL 版本、模式與適用訊號，不用 MariaDB 語意替代 | MySQL DBA／環境負責人 |
| MariaDB primary＋replica，原生非同步複製 | 同上各狀態與活動／無寫入期；MariaDB 來源語意、進度／lag／錯誤及 binlog 保留風險 | 人員準備基線與狀態，保留實際 MariaDB 版本、模式與適用訊號，不用 MySQL 語意替代 | MariaDB DBA／環境負責人 |
| MySQL 真實雙通道 | 兩條同時存在且身分可區分的通道；正常、一條停止而另一條健康／前進、其後恢復；來源與適用 GTID 範圍 | 同一真實拓樸完成上述觀察並綁定每個來源／通道；兩次單通道取樣不可抵用 | MySQL DBA |
| MariaDB 真實雙通道 | 同上狀態、來源／通道與適用 GTID／domain 範圍 | 同一真實拓樸完成上述觀察，保留 MariaDB 專屬語意與通道對應 | MariaDB DBA |

每組須留存觀察起訖、取樣間隔、來源／訊號時間與單位、政策、負載／逾時預算及實際缺樣；不延長或縮窗求通過，不要求耗盡儲存。未重現的錯誤、NULL／哨兵、矛盾或特殊值只能陳述 F 覆蓋。PostgreSQL 其他複製模式與未測拓樸仍未驗收。

## R：八條真實 RDS 操作路徑

每列目前已有證據均僅為合成 F 行為邊界，缺少整條真實事件證據鏈；原因是本 Story 不選擇或操作雲端環境。每列都必須取得下節的完整證據鏈，至少一次正向角色／端點轉換及一次恢復至事先指定複製／HA 保護要求的正向實證與後續有限觀察窗。只有「切換完成但保護未恢復」不能解除缺口。

| 必要路徑 | 缺項 | 解除條件 | 接手角色 |
| --- | --- | --- | --- |
| PostgreSQL Multi-AZ DB instance 切換 | 完整事件鏈、實際轉換及保護恢復正例 | 提供本路徑新演練或逐項適用的合格歷史事件證據 | RDS／PostgreSQL DBA、應用負責人 |
| MySQL Multi-AZ DB instance 切換 | 同上 | 同上，綁定本引擎／操作 | RDS／MySQL DBA、應用負責人 |
| MariaDB Multi-AZ DB instance 切換 | 同上 | 同上，綁定本引擎／操作 | RDS／MariaDB DBA、應用負責人 |
| PostgreSQL read replica promotion | 同上，含 promotion 後保護及適用重建／收尾 | 提供 promotion 專屬證據，不以 instance 切換替代 | RDS／PostgreSQL DBA、應用負責人 |
| MySQL read replica promotion | 同上 | 同上，綁定本引擎／操作 | RDS／MySQL DBA、應用負責人 |
| MariaDB read replica promotion | 同上 | 同上，綁定本引擎／操作 | RDS／MariaDB DBA、應用負責人 |
| PostgreSQL Multi-AZ DB cluster 切換 | 完整事件鏈、實際轉換及保護恢復正例 | 提供 cluster 專屬證據，不以 instance 切換或 promotion 替代 | RDS／PostgreSQL DBA、應用負責人 |
| MySQL Multi-AZ DB cluster 切換 | 同上 | 同上，綁定本引擎／操作 | RDS／MySQL DBA、應用負責人 |

MariaDB Multi-AZ DB cluster 為本策略不適用項，不是第九條必要路徑。八條是證據路徑數，非同時存在的環境數；可分時建立或共用適用 B1 資源，但 B1 通過不能代替 B2 觀察。Aurora、其他雲平台與自管平台層不在範圍。

每條 R 路徑各自缺少並須補齊：

1. 事件／演練識別、操作類型、來源／目標與前後節點、拓樸、端點、時間及對象對應。
2. 新演練的隔離、有效批准、人工操作、寫入／流量／連線控制與交接；歷史平台自動事件不偽造人工批准，歷史人工操作缺批准仍保留合規缺口。
3. 計畫內 RDS 唯讀平台與 dbcli 引擎觀察，適用設定、事件、CloudWatch 及可見性限制。Multi-AZ instance standby SQL 不可見須如實記錄，不能由 L 或虛構查詢補足。
4. 事先固定且與事件截點相容的資料／業務及應用恢復基準、實際資料驗證與應用驗證。需寫入的探測由人執行；連線成功不足以證明應用恢復。
5. 可判定的 RPO／RTO 目標、參考時間、復原點／遺失範圍或界限、起訖及計算依據；平台耗時、應用恢復、驗證與等待分開保存。lag／LSN／GTID 不代替業務 RPO，不刪除等待美化 RTO。
6. 切換後保護要求、新拓樸／設定與觀察窗、適用的回切／重建批准及人工步驟、清除批准核對、人工收尾或殘留／原因／責任人。promotion 不假設可一鍵撤銷，也不要求所有操作回到原拓樸。

角色、資料、應用、RPO、RTO、保護恢復分項判定；RPO／RTO 超標可為 not-met，不強迫業務目標 met，但量測不足仍是缺口。先前保護未恢復及後來恢復分別保留有時間範圍的結論，清除失敗明示未收尾，不覆寫歷史。
