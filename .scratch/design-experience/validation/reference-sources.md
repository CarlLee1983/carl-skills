日期：2026-10-23。分支：`feat/design-experience-reference-sources`。規格：[spec](../../design-experience-reference-sources/spec.md)。

方法同[改善模式驗證](improve.md)：每個情境由新的 general-purpose 代理獨立執行，只讀技能目錄與夾具，不讀 docs、`.scratch` 其他檔案、README、GLOSSARY，不建檔、不用瀏覽器；輸出第一則回覆、規則追溯與技能文字的模糊處。判定由主代理對照 `docs/design-experience/acceptance.md`。RED 跑在變更前的技能副本（暫存目錄），GREEN 跑在工作樹。

夾具在 [fixtures/reference-sources/](fixtures/reference-sources/)：`target-mockup.html` 以 Playwright 1.56.1 渲染成 1440×1000 的 `target-mockup.png` 與 820×560 視窗裁切的 `target-mockup-cropped.png`；`capabilities.md` 為只有後端 API 的寵物美容預約專案。圖中埋入錯字、lorem ipsum、旋轉重疊的卡片、AI 心情指數、GPS、會員點數、評價、「Partnered with airbnb」、emoji 圖示、雙主按鈕、低對比小字，且未畫任何空白或錯誤狀態。

依 GREEN 代理指出的模糊處修正（措辭補強）：刪除限於裝飾或捏造宣稱，待產品決定為需要缺少能力的合理使用者任務，免能力的內容（人員介紹、店家提供的真實評語）屬改做法；圖上的名稱與 logo 在使用者確認前為暫名；對圖片的品味基線檢查為目測、屬部分檢查，看不到的節記未檢查；一項發現一個問題；主題起手第一輪同時做審查與訪談，原型取代 style tile 一輪；以例子界定值得另提方向的結構問題；SESSION 在開始保存紀錄後才記錄來源。夾具 `capabilities.md` 原本寫入了使用者訊息，與 T7 的訊息不一致，已改為由情境給定。

措辭補強後重跑 T1、T7（夾具已修正），兩者皆通過。依重跑回饋再補五處：改做法的例子原為「心情指數改成時長與價格」，與刪除的「捏造數據」衝突，改為「旋轉疊放的卡片改成能重排的列表」；意圖不明時明訂可行性審查照做、依圖建原型等使用者回答；「看不到」涵蓋被其他元素遮住的部分；值得另提方向的結構問題改為「主要任務從畫面到不了，或主要任務需要的內容在版面上沒有位置」，靠重排既有元素就能修的版面屬改做法；視覺方向技能只在目標稿的視覺語言內細修處理 1。程式碼審查（Standards／Spec 兩軸）後再修兩處：「目標稿即 A 與 1」限定在主題起手（原文未限定模式，功能起手與改善的分支留給工單 03），並在視覺語言段明寫原型取代 style tile 一輪。

以最終文字重跑 T1、T7，兩者皆通過：

- **行為**：T1 判定主題起手加目標稿，22 項發現各附類型與決定，被遮住的區塊標「看不到」並說明原圖也看不到，未另提方向 B；T7 推薦目標稿讀法、審查照做、建原型等回答。

T7 重跑指出「元素互相遮住時索取原圖無意義」，已改為「原圖看得到時才索取」，此後未再重跑。
