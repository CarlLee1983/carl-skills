# design-experience 改善模式驗證

日期：2026-10-21。分支：`feat/design-experience-theme-first`。工單：[05](../issues/05-improve-existing-design.md)。

方法同[主題起手驗證](theme-first.md)：每個情境由新的 general-purpose 代理獨立執行，只讀技能目錄，不讀 docs、`.scratch`、README，不建檔、不使用瀏覽器；輸出回覆與規則追溯。判定由主代理對照 `docs/design-experience/acceptance.md`。未另開獨立評分代理。

| 情境 | 夾具摘要 | 判定與觀察 |
| --- | --- | --- |
| I1 | Vue 3 + Element Plus 茶葉電商後台，/orders 14 欄表格，「訂單頁用起來很不順」 | 通過。判定改善並附依據；現況記為依程式碼推得、未見畫面並索取截圖；Q1–Q5 輪次附建議；自我檢視標為專家檢視；未直接提出重新設計。 |
| I2 | Astro 記帳事務所官網，附截圖描述，「首頁很醜」 | 通過。含糊抱怨拆成 a／b／c 具體解讀；P1–P6 附層級與來源；emoji 依品味基線列入；建議由深到淺並允許對調。 |
| I3 | 延續 I1，使用者已回答 Q1–Q5（倉管、漸進、保留 Element Plus 與選單） | 通過。問題清單排序、使用者回報與代理檢視分開；依層級建議處理順序；必須保留的部分不動；保存前先徵求授權。 |
| I4 | Next.js 診所預約站已上線；I4a「立即預約按鈕太搶眼」、I4b「背景改成 #888888」 | 通過。I4a 判定改善模式細節層，截下現況、不跑完整診斷；I4b 判定為單純 CSS 修正，不啟動技能。評估者指出微調該在隔離複本或正式碼進行未寫明——已補「隔離複本」，並以該問題作為整份問題清單。 |
| I5 | Laravel + Vue 志工排班，三個月前以本技能定稿，上線版與定稿不同 | 通過。接續原 SESSION，模式依證據改為改善；現況取上線版，上線與定稿落差列為 P2、P3；只依程式碼的檢視標為部分。評估者指出未經設計就上線的功能歸屬、使用者是否已習慣偏離——已補。 |
| R3 | React 庫存工具，新功能 API 尚無畫面 | 通過（回歸）。判定功能起手，明言使用者未表示不滿故不走改善。 |

依評估修正（措辭補強，未重跑情境）：漸進範圍改為「導覽、路由與必須保留項不動，受影響畫面內可重組」並問共用頁首頁尾；一題跨兩層時取改動較小者；嚴重度用高／中／低附理由、頻率未知時標暫定；未確認的代理檢視留在清單並標來源；新增行銷頁的訊息層；只靠截圖或程式碼的檢視標為部分；沒有瀏覽器時只索取截圖；事實題不需建議答案；同一請求新增功能又抱怨舊畫面時分別判定。

I4、I5 於 `grill-with-docs` 拷問（工單 05 的 Q1–Q10）定案後新增；兩處補強為措辭澄清，未重跑。
