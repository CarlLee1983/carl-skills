# design-experience 品味基線擴充驗證

日期：2026-10-22。分支：`feat/design-experience-taste-baseline`。變更：新增 `references/taste-baseline.md`（字級、間距與對齊、色彩與對比、主次動作、表面、圖示、溢出、檢查方式），原本 SKILL.md 的圖示規則併入；SKILL.md、improvement.md、collaboration.md 改為連結；`GLOSSARY.md` 更新品味基線定義；`acceptance.md` 新增 6 列情境。

方法：每個情境由新的 general-purpose 代理獨立執行，只讀技能目錄，不讀 docs、`.scratch`、README、GLOSSARY 或預期答案；B2、B3、B6 不建檔、不用瀏覽器，B1 可寫入暫存目錄。判定由主代理對照 `docs/design-experience/acceptance.md`。未另開獨立評分代理。

| 情境 | 夾具摘要 | 判定與觀察 |
| --- | --- | --- |
| B1 | 主題起手攝影作品集，訪談完成，「開始做吧」；假設本機沒有視覺方向技能 | 通過（部分驗證）。產出 3 個附概念的處理與 SESSION，記下沒有合適的視覺技能；基線逐節記錄，無截圖的項目標 partial，從 token 計算的對比註明「僅程式碼」。主代理以 Playwright CLI 在 390px 與 1440px 截圖：三個處理在字體、底色、圓角上看得出差異；圖示是 inline SVG，沒有 emoji；390px 時內文每行約 20 個中文字。代理指出 16px 內文與每行 25–40 字在手機寬度互相衝突——已修正。 |
| B2 | 功能起手會員點數後台，品牌 mint #8FD3C7 底配白字、次要文字 #A0A0A0 | 通過。保留品牌值，算出 1.71:1 與 2.61:1 記為發現，並排附上合規變體交使用者決定；說明數值是從 token 計算的、截圖後要複查。代理指出「最小合規變體」沒有定義——已修正。 |
| B3 | 功能起手出貨佇列，唯一視覺技能 `whisper-ui` 含淺灰小字、10 個字級、ghost 主要按鈕、emoji | 通過。照常選用該技能，把違反基線的規則逐條推翻或調整並說明衝突；三個處理的密度不同，基線沒有讓它們收斂成同一風格。代理指出 CJK 字體算不算一套、「小一級」的基準、卡片與畫面的主要動作如何並存——已修正。 |
| B6 | 改善模式 Hugo 部落格，只有使用者的文字描述，「文章頁讀起來很累」 | 通過。現況標為未在畫面上看過，自行檢視標為專家審查、partial；P1–P10 各引用基線的節，問題依層級分類，沒描述到的節標未檢查。代理指出連結只靠顏色區分、整頁橫向捲動、沒有「未檢查」狀態——已修正。 |

依評估修正（皆為措辭補強，未重跑情境）：最小合規變體定義為「改動最少、各值保留色相」；字體改為最多兩種角色，拉丁字與搭配的 CJK 字算同一角色；字級涵蓋程式碼與 meta；行長只適用寬螢幕，窄螢幕維持內文字級、行寬填滿欄位；連結比照狀態，要搭配第二種提示；強調色標示畫面的主要動作，列內動作只在它就是畫面主要任務時才用強調色；整頁不可橫向捲動；檢查狀態改成通過、已修正、未通過、未檢查，「fixed」與「被來源固定」不再撞名。

未處理（判斷為不影響基線本身，留待後續）：視覺來源「部分固定」時，沒固定的維度要不要提處理（B2）；協作技能被推翻多少條後就不再算 fitting（B3）；使用者口述的現況在證據等級中的位置（B6）；比較切換列等評估外框是否受基線約束（B1）。
