### React Native 用 HTML 原型模擬是否恰當

**選擇本身恰當。** 專案沒有程式碼也沒有前端宿主，使用者又要求「先給我看東西」。SKILL.md 第 82 行允許做成單一離線 HTML。手機框固定為 390×844（`directions-v1.html` 第 49 行），字級採 iOS 慣例 17/15/13，觸控目標至少 44px，比較頁也寫了 Android 的對應做法，對比較視覺和結構來說足夠。

**限制的交代不完整：**

1. 給使用者的訊息只說「還沒在 iOS／Android 模擬器或實機上看過」（transcript 第 25、74、129 行）。三件事只寫在 SESSION（第 44、100 行），沒有告訴使用者：
   - 原型是 HTML，只畫了 iOS 外觀，Android 沒有畫面；
   - 字體是由 macOS Chromium 渲染的；
   - 互動是網頁點擊，不是原生的手勢、sheet 或返回行為。
2. **已驗證：處理 3 的「圓體大數字」在 Chromium 根本沒有顯示。** 字型堆疊是 `ui-rounded, "SF Pro Rounded", -apple-system`（`style-tiles-v2.html` 第 281–282 行）。評審在 Chromium 量測，`ui-rounded` 與 `-apple-system` 渲染出的寬度完全相同（224 對 224 px），表示退回了系統字。但處理 3 的概念和取捨（transcript 第 21 行說「用圓體大數字」「Android 也要打包圓體」）正是靠這個字型成立的。設計師說截圖都「逐張看過」，卻沒有發現截圖裡不是圓體。這屬於 HTML 模擬原生字型的典型落差，也是設計師說法與評審所見不一致的地方。
3. 在 390 寬的視窗下，手機框會被 `zoom: .84` 縮小（`directions-v1.html` 第 29 行）。所以設計師記的「390 寬不橫向捲動」檢查的是比較頁，不是 390pt 裝置。390pt 裝置畫面要在 1280 寬截圖的手機框裡才看得到。這個結果仍然成立，只是 SESSION 沒有分清兩者。

## 設計師執行偏差

1. **最重要的一項：HTML 模擬的限制只寫進 SESSION，沒有告訴使用者。** 交付訊息沒說原型只畫 iOS、字體由 Chromium 渲染。處理 3 的圓體在截圖中沒有渲染，設計師卻仍以「圓體大數字」介紹它，並宣稱截圖都逐張看過。
2. `directions-v1` 沒有逐節記錄品味基線，tab 標籤的 11px 使字級變成六級。
3. 深色重調實際還改了 accent、ink、income 等值（v2 第 251–253 行）。transcript 第 51–54 行只講三項改法，SESSION 也只多記了殼層。這些改動都只在深色範圍內，不違反「只動深色」，但變更說明不完整。
4. 微調紀錄寫成多行，技能要求一行，屬於格式小偏差。

## 限制

- 沒有在 iOS 或 Android 模擬器上檢視。評審截圖都來自 Playwright Chromium，視窗是 390×844 與 1280×1000。
- `impeccable` 是否真的被呼叫，只能依 SESSION 自述判斷，無法從產物證實。
- 沒有重跑設計師的互動腳本。試用任務的點按數與超支預覽，只核對了原始碼邏輯和靜態截圖。
