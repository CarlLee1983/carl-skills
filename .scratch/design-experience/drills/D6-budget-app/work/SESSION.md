# 記帳 App 介面設計 SESSION

## 任務與目標

- **專案位置：** 本工作區（`work/`）；專案還沒有任何程式碼或設計資產。
- **原始需求（第 1 回合）：**「幫我設計一個記帳 App 的介面，React Native，之後上架 iOS/Android。要有深色模式。問題不要問太多，先給我看東西。」
- **進入模式：theme-first。** 依據：fixtures 為空，沒有既有介面、品牌、tokens 或設計系統。
- **產品類型（推斷）：** 功能型產品（個人理財工具，手機 App）。依據：使用者自述「記帳 App」。interview.md 沒有手機 App 的題組，這裡借用「功能型產品」的題組，並把「日常使用、單手、快速輸入」列為假設。
- **硬性限制（已確認，來源：使用者）：** React Native；iOS 與 Android 上架；深色模式必須有。
- **協作技能：** 視覺處理由 `impeccable` 塑形（描述涵蓋原生 iOS/Android 畫面），套用它的 Operate 模式規則、craft floor、ios.md／android.md 原生規則。`mobile-native` 已檢查但不適用：它只處理行動網頁的平台層，明確排除 React Native。impeccable 的 init 訪談、PRODUCT.md、DESIGN.md、決策頁與 concept-seed 沒有執行，原因是這個流程由本 SESSION 主導，而且使用者要求少問問題；impeccable 的 `context` 已執行，回報沒有產品脈絡。

## 訪談（theme-first）

第 1 回合使用者要求先看東西，所以全部採用建議答案。第 2 回合使用者說「其他你決定」，沒有更正下列內容。因此下列項目維持**設計假設**，屬於使用者委託設計師決定，並非使用者明示確認：

| 項目 | 假設 |
| --- | --- |
| 對象與主要動作 | 台灣的一般個人使用者，每天隨手記帳；最重要的動作是「花完錢後幾秒內記一筆」，其次是「看本月還剩多少」 |
| 第一個要設計的流程 | 首頁看餘額 → 記一筆 → 回到首頁看到更新 |
| 語言、幣別 | 繁體中文（台灣）、新台幣 |
| 品牌資產 | 沒有，可以自由建立 |
| 情緒形容詞 | 清楚、安心、輕快；避免：像銀行對帳單一樣冰冷、像遊戲一樣吵 |
| 深淺色 | 兩種都是一等外觀，預設跟隨系統 |

**留給產品規劃的範圍問題（未決）：** 多帳戶或信用卡、分帳、雲端同步與登入、發票載具匯入、定期扣款、多幣別、預算是整月總額還是逐類別設定。這些都不由本設計決定。

## 目前階段

結構方向比較：已交付 A/B/C，等使用者選擇並回報試用結果（喜歡的地方、卡住的地方，分開記錄）。

第 3 回合使用者問「下一步？」。已說明後續路徑：選結構 → 深化主流程與狀態 → 細修／定稿 → 交接。這是提問，沒有授權正式實作，也沒有選定方向，仍在等選擇。

第 4 回合（2026-10-23）使用者暫停：「我先想想要選哪個，今天先到這裡。」**續作入口：** 先確認本檔列出的檔案都還在，再問使用者的結構選擇（A/B/C，建議 B）、試用回饋（喜歡的地方、卡住的地方，分開記錄），以及處理 2 深色 v2 是否已經可以。不要重問已定案的視覺處理 2 和跨平台 b。

視覺：已選處理 2，深色 v2 重調已交付，等使用者確認是否還髒。

## 方向與決策

- **視覺處理（數字）：**
  - **1 發票明細：** 密、平、金額用等寬數字、細線分組、統一發票綠只用在主動作。
  - **2 預算信封：** 藍綠色殼層承載餘額、類別色圓章、柔和層次、從容間距，全部用系統字。
  - **3 今日額度：** 圓體大數字、鈷藍滿版摘要、粗線圖示、膠囊控制。它把首頁主角從「月餘額」換成「今天還能花」，屬於產品觀點，需要使用者決定。
- **視覺處理選擇（第 2 回合，使用者）：** 選 **2 預算信封**。理由：未陳述（原話「2 不錯」）。附帶回饋：「深色模式看起來髒髒的」，以細節修正處理，見修正紀錄。
- **跨平台外觀（第 2 回合，使用者委託設計師決定）：** 採 b。外觀統一；導覽、返回、彈窗、圖示各用平台原生元件，也就是 iOS 用 sheet／SF Symbols，Android 用 Material 3 FAB／bottom sheet／系統返回。原型仍以 iOS 畫面呈現，Android 對應寫在比較頁說明裡。
- **結構方向（字母），處理 2 視覺，同一份樣本資料：**
  - **A 流水帳優先：** 首頁是餘額殼層＋最近明細，用浮動「記一筆」叫出 sheet。試用任務點按 4 次。代價：首頁看不到各類別剩多少。
  - **B 打開就記：** 首頁就是數字鍵，餘額縮成頂端一行，選類別時即時顯示「該類還剩 → 記完剩」，最近紀錄收在可展開的抽屜裡。點按 3 次。代價：首頁沒有全貌，初見可能看不出是什麼 App。
  - **C 預算信封：** 首頁是 6 個類別信封（剩多少／超支），點信封直接記進該類。點按 4 次。代價：每類都要先設預算，這是產品決策；明細被擠到下方。
  - 共通：三個方向的記一筆面板都會預覽「該類還剩 → 記完剩」，超支時以紅字標示「（會超支）」。
- **設計師建議（尚非決策）：** B，因為假設中的主要動作是「花完錢幾秒內記一筆」，B 最快。若使用者更在意分類控管，就選 C。
- **使用者選擇（結構）：** 尚無。

## 設計與入口

- `prototypes/directions-v1.html`：結構方向比較，是本輪主入口。上方可切換 A/B/C 和淺/深色，hash 例如 `#d=B&m=dark`；「重設樣本」會還原資料。三個方向共用記憶體中的資料，切換時保留。月份、分頁、「查看」「全部」按下後會提示尚未設計。
- `prototypes/style-tiles-v2.html`：視覺處理比較，只把處理 2 的深色改成重調版；處理 1、3 與 v1 相同。
- `prototypes/style-tiles-v1.html`：保留作為深色重調前的版本。style-tiles 兩版都是單一離線 HTML，上方可以切換處理 1/2/3 和淺/深色，hash 例如 `#t=2&m=dark`。
- 樣本與實際的區分：全部金額、商家、預算都是樣本。記一筆的數字鍵、類別、收支切換、儲存都可以操作，但只寫進頁面記憶體，重新整理就消失。分頁、月份、「查看」按下後會提示尚未設計。
- 圖示：Lucide（ISC），以 inline SVG 放在檔內。依跨平台決策 b，正式 App 的 iOS 用 SF Symbols、Android 用 Material Symbols；原型中的 Lucide 只是替身。
- 截圖：
  - 第 1 輪：`screenshots/v1-t{1,2,3}-{light,dark}.png`、`screenshots/v1-focus-*.png`、`screenshots/v1-narrow.png`。
  - 深色重調：`screenshots/refine-t2-dark-{before,after}.png`。
  - 結構方向：`screenshots/dir-{A,B,C}-{light,dark}.png`、`screenshots/dir-{A,B,C}-entry.png`、`screenshots/dir-B-drawer.png`。
