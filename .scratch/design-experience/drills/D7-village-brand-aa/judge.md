# D7 里辦報名（功能起手・品牌色未達 AA）評審

**總判定：部分通過。** 品牌色未達 AA 的處理（保留原值、並排最小合規變體、記錄決定、F2 知情不合規）、結構比較、長者可用性與交接都做到位；扣分在視覺語言階段：品牌色＋里徽並沒有固定視覺，但定稿前沒有做視覺處理比較，原型的公告頁也和交接寫的「只加連結」互相矛盾。視覺階段被跳過，主因是技能沒有定義「部分品牌」和「提前定稿」該怎麼處理，屬技能缺陷；公告頁的矛盾則是執行偏差。

## 重點問題：品牌色＋里徽算不算「視覺來源已固定」

不算。理由如下：

- SKILL.md:23 判定功能起手時，把「fixed visual source (brand, tokens, design system)」當作判斷依據之一；SKILL.md:100 則寫「Start from the project's visual source … when it fixes the visuals, say so and move on」。兩處都用 fixed／fixes，意思卻不同：前者是「有一個不可改的視覺來源存在」（決定進入模式），後者是「這個來源決定了全部視覺」（決定能否跳過視覺處理）。
- 本案夾具寫明「沒有其他設計系統」（fixtures/project.md），只指定一個主色與里徽。字體、字級、密度、表面、圖示都沒有規定，所以照 SKILL.md:100 與 :106 的完成條件，應該在結構選定後，於 C 上做 2–3 個視覺處理（acceptance.md:56「功能起手，結構已選定，專案沒有固定視覺來源」）。另外，公告頁屬於「Ad-hoc styles of an existing interface do not fix the visuals」。
- 設計師自己在第 2 回合也這樣判斷：transcript.md:67「品牌目前只固定了主色和里徽，其他部分還沒有定」。可見設計師分辨得出來；跳過比較是因為使用者在第 3 回合把「選 C」和「定稿」放在同一句（transcript.md:71）。

結論：**算技能缺陷為主，執行偏差為輔。** 照 SKILL.md:122，「定稿」就是凍結並交接，代理照做是合規的。但技能沒有規定：定稿時還有一個應做而未做的視覺階段，代理要怎麼揭露、要怎麼記錄接受狀態。SKILL.md:128 只涵蓋「visuals were never reviewed as rendered screens」，acceptance.md:57 只涵蓋「瀏覽器不可用時說定稿」，兩者都不適用本案（畫面有渲染、使用者看過 C v1）。設計師自己發明了「依 v2 畫面接受，未經處理方案比較」（SESSION.md:90），方向合理，但這不是技能規定的狀態。執行面的偏差是第 1 回合把「現有公告頁和品牌色、里徽」稱為「固定的視覺來源」（transcript.md:9，SESSION.md:7 沿用），而且視覺階段會被跳過這件事是定稿之後才告知（transcript.md:89），不是在凍結之前。

## 畫面品質發現（評審自行截圖，`judge-shots/`）

- `v2-open-e1-390.png`、`v2-open-e1-1280.png`：層級清楚，每張卡由一個主要動作帶頭（深橘「送出這位的報名」），額滿與截止用紅字搭配文字標示，焦點框可見性沿用設計師的檢查。320 寬（`v2-notices-320.png`）沒有橫向溢出。整體符合基線。
- 頁首白字標題 2.02:1 在截圖上確實偏淡（`v2-list-390.png`），已列為 F2 知情不合規，處理正確。
- 底部原型切換列在全頁截圖中蓋住內容，但 body 有 `padding-bottom: 168px`（registration-c-v2.html:34），實際捲到底不會遮擋，屬全頁截圖的假象，不算缺陷。
- **公告頁和交接矛盾**：原型的「最新公告」（`v2-notices-320.png`）和現況（`work/screenshots/current-notices-390.png`）比較，有幾處改動：移除了「詳細內容」按鈕（兩份原型 grep「詳細內容」皆為 0）、日期改深色、內文放大、新增主選單。可是第 1 回合說公告頁問題「不在這次範圍」（transcript.md:21）、Q3 說「只會加連結，不動既有內容」（:27），交接實作順序第 5 步也寫「只加連結，不動既有內容」（SESSION.md:93）。開發者照原型或照交接，會做出不同的公告頁。
- 視覺語言實質上是新創的：#A16C00 按鈕、18px、56px、卡片樣式都和現有公告頁（15px、#F7A600 白字小按鈕）不同。依交接只在公告頁加連結的話，同一網站會出現兩套視覺，交接沒有處理這點。這正是跳過視覺處理比較的後果。
- 設計師自稱的驗證（溢出 0、焦點、對比值）和評審看到的一致，沒有發現不實陳述。

## 設計師執行偏差

1. **公告頁原型和交接矛盾（中）**：原型改了公告頁的樣式與按鈕，交接和對話卻寫「只加連結，不動既有內容」，而且改動沒有記入 SESSION。
2. **第 1 回合誤稱公告頁與品牌為「固定的視覺來源」（低）**：違反 SKILL.md:100 的「Ad-hoc styles … do not fix the visuals」；第 2 回合已自行更正，但 SESSION.md:7 沒有改。
3. **視覺階段跳過的告知放在定稿之後（低）**：transcript.md:89 才說明；SESSION.md:81「視覺語言在結構選定後處理」成為過期敘述。
4. **「依 v2 畫面接受」說法過頭（低）**：使用者只看過 C v1；v2 是照 Q3、Q4 建議定稿後才建的。
