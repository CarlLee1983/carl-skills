# 和平里活動報名網站｜設計 SESSION

## 任務與目標

- 專案材料：`../fixtures/project.md`、`../fixtures/notices.html`（現有公告頁）
- 原始需求：里辦要做活動報名網站；品牌色里長指定 #F7A600、按鈕白字；報名 API 已完成；長輩為主。
- 進入模式：**Feature-first**。依據：已有介面（公告頁）與固定視覺來源（品牌色、里徽不可改）；新增的報名介面不在現有頁面涵蓋內，使用者未表示對公告頁不滿。
- 使用者：60 歲以上里民，常由子女或志工代操作（來源：project.md）。
- 核心任務：找到活動 → 報名（姓名、電話、人數）→ 取得報名序號；之後以序號＋電話取消。
- 能力邊界（來源：project.md）：`GET /events`、`POST /events/{id}/registrations`、`POST /registrations/{id}/cancel`。不存在會員、登入、付款、簡訊通知。

## 視覺來源與發現

- 品牌色 #F7A600、按鈕白字（里長指定）；里徽圓形橘黃底白字「和平」不可改（標誌不受文字對比規範約束）。
- **發現 F1（品牌值低於 AA）**：白字對 #F7A600 為 2.02:1，按鈕文字（需 4.5）與橫幅大字（需 3）都不足；按鈕外框對頁面底色 #FFFAF0 為 1.94:1（需 3）。證據：`screenshots/contrast-1280.png`、`screenshots/contrast-390.png`。依基準保留原值並並列最小合規變體：
  - 改底色（改 1 值）：按鈕／橫幅底改同色相 #A16C00，白字 4.51、外框 4.33。
  - 改字色（改 2 值）：保留 #F7A600，字改 #333333（6.26），按鈕加 #A16C00 邊框（4.33）。
  - 決定（第 2 回合）：按鈕採「改底色」#A16C00 白字；里徽與頁首（標題列）保留原本 #F7A600。理由：里長堅持此色並喜歡白字。
- **發現 F2（頁首標題白字仍不足）**：使用者保留橘黃頁首；若標題維持白字，對比 2.02:1，低於大字 3:1。保留使用者的選擇為預設，原型切換列可切到最小合規變體「頁首標題改深字 #333333」（6.26:1，只改一個值）。證據：`screenshots/v1/A-1-list.png`（白字）、`screenshots/v1/H-title-dark.png`（深字）。待使用者決定（第 2 回合 Q2）。
- 觀察（不在本輪範圍）：公告頁日期 #999 對白 2.85、頁尾 #aaa 對 #FFFAF0 2.23、內文 15px；屬現有公告頁，僅記錄。

## 已確定（第 2 回合）

- 主要操作者：子女或志工用手機代填居多，長輩自己操作也有（Q2 → b 為主、a 也有）。
- 入口：同一網站；公告裡有報名的活動放「我要報名」，連到該活動的報名（Q3 → a）。
- 忘記序號：里辦接受電話代為取消（Q4）。完成頁與取消頁都寫上里辦電話。

**定稿與交接（第 3 回合）**。使用者選 C 並定稿；定稿版本為 `prototypes/registration-c-v2.html` v2。未授權正式實作。

## 結構方向

- **A 清單＋單頁表單**：沿用公告卡片的活動清單，按「我要報名」進入一頁表單，完成頁顯示序號。適合：長輩自己看清單、和現有公告頁一致。代價：代填多位時要來回「完成頁→再報一位」。
- **B 一步一題**：一頁只問一件事（姓名→電話→人數→確認），有進度條；取消也逐步。適合：不熟手機的長輩自己操作。代價：代填者每位要 5 個畫面，最慢。
- **C 代填工作台**：活動列表就地展開表單，送出後保留活動、清空表單接著報下一位；下方累積「這次幫忙報名的紀錄」，可逐筆取消並一鍵複製序號傳給家人。適合：子女／志工連續代填，並解決沒有簡訊時序號怎麼交到長輩手上。代價：頁面較長；紀錄只存在這支手機這次畫面（重新整理即消失，是否要保存在手機上待決）。
- 設計師建議：C（代填居多，且序號交接是無簡訊下的主要風險）。
- **使用者選擇（第 3 回合）：C**，未另外陳述理由（同意設計師建議）。

## 決定紀錄（第 3 回合）

- 結構：C 代填工作台。
- 頁首標題：維持白字。理由：里長喜歡白字。**已知不合規 F2**（2.02:1，大字需 3:1），使用者知情下決定；合規替代為標題改 #333333（6.26:1），截圖 `screenshots/v1/H-title-dark.png`。
- Q3：代填紀錄存在這支手機（b），並提供「清除這支手機上的紀錄」。
- Q4：使用者回「照建議」——每筆最多 4 位、「需攜伴」＝需有人陪同且人數至少 2 位。來源為使用者轉述，**里辦是否正式確認未陳述**，實作前建議再確認一次。
- 試用回饋：使用者表示不另外提供「喜歡哪裡」與「卡在哪裡」。**沒有真人試用證據。**

## 原型假設（第 3 回合起 Q4 兩項改為使用者同意）

- 每筆報名最多 4 位（API 未說明上限）。
- 「需攜伴」解讀為「需有人陪同，人數至少 2 位」。
- 序號格式 HP0137 為範例；實際格式依 API。
- 電話驗證：0 開頭 9–10 碼（含市話）。

## 假設（未經確認）

- 以手機為主要裝置，桌機可用。
- 內文 18px、主要按鈕高 56px 以上，照顧長輩閱讀與點按。
