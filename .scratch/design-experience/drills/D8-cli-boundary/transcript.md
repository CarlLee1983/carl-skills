先講結論：我把這次的「介面」理解為 **dbcli 在終端機裡的使用體驗**（指令輸出、連線與權限提示、錯誤訊息、匯出進度），而不是圖形介面。README 的 Non-goals 明寫「No GUI. dbcli is designed for agents and terminals; a graphical client is out of scope.」，所以加一個 GUI 是產品範圍的決定，不是設計能直接拍板的事；如果你真的要 GUI，請見 Q1。

**這一回合的交付**：一份可修正的理解（下方），加上第一輪訪談問題。工作紀錄放在 `work/SESSION.md`。你回覆後，下一回合我會交出 2–3 個結構方向（例如「每個指令前都顯示連線脈絡」對「只在危險時顯示」），用同一組情境以可重播的終端機逐字稿原型（單一離線 HTML，模擬終端畫面，不是 GUI）讓你比較。

### 我的理解（請直接糾正）

- **進入模式**：theme-first。依據：dbcli 是 CLI 專案，沒有既有的圖形介面、品牌或設計系統；終端輸出目前是單行英文錯誤，沒有成文的輸出規範。
- **產品類型**：功能型工具（接近後台工具一類）。依據：權限分級 read-only／read-write／admin、黑名單、匯出、schema 查詢，都是操作型任務。*（推論）*
- **使用者與情境**：兩種讀者共用同一個輸出——在終端機裡操作的人，以及解析輸出的 AI agent。有來源的痛點都來自人：新手不知道自己在哪個連線、哪個權限等級下操作；大量匯出沒有進度。
- **核心任務**：在「確定自己連對地方、權限對」的前提下查詢或匯出資料；被拒絕時知道原因與恢復路徑。
- **先設計的代表流程**：新手 `dbcli query` 一條寫入 SQL → 被 `permission denied (read-only)` 擋下 → 看得懂現在的連線與權限、知道下一步該做什麼。第二個流程是 `dbcli export` 大量資料時的進度與完成回饋。
- **約束（有來源）**：不做 GUI；支援六種資料庫；三級權限；敏感欄位黑名單；匯出 csv／json。
- **假設（無來源，可推翻）**：資料（查詢結果、匯出內容）應走 stdout，狀態、脈絡、進度走 stderr，這樣管線與 agent 解析不受影響；非 TTY 或 agent 情境下不顯示動畫與顏色。
- **資料限制**：我目前只讀到專案概述，還沒看到實際的輸出程式碼、`.dbcli` 設定格式與完整 README。若你方便給 repo 路徑，我會自己讀，避免設計出現有能力不支援的東西。

### 第一輪問題（可以只回「Q1 a，Q3 改 b」）

**Q1　「介面」指的是什麼？**
a. dbcli 的終端體驗：脈絡顯示、錯誤、進度、表格輸出、`init` 引導。**建議 a**——符合 README 的 Non-goals，且兩個已知痛點都在這一層。
b. 一個圖形介面（桌面或網頁）。這會推翻 Non-goals，屬於產品範圍決定，要先走專案的規劃入口；我可以在你明確授權下做一個隔離的概念原型供討論，但不會把它當成產品方向。

**Q2　主要讀者的優先順序？**
a. 人優先，agent 不能被破壞（預設輸出給人看，`--json` 或非 TTY 時給機器）。**建議 a**——痛點都來自人；agent 靠結構化模式就能穩定。
b. agent 優先，人看到的是 agent 輸出的附帶品。
c. 兩者同等，所有輸出都要同時好讀又好解析。

**Q3　連線脈絡有沒有「環境」的概念？** 例如連線會被標成 production／staging／local。
a. 有，或應該有——脈絡顯示要把 production 標得最醒目。**建議先答事實**：這會決定「誤連正式環境」是不是要處理的最高風險。
b. 沒有，只有連線名稱與權限等級。

**Q4　脈絡要多常出現？**（這題會成為下一回合的方向比較軸，先問你的直覺）
a. 每個指令都在 stderr 印一行精簡脈絡（例：`● prod-mysql · read-only`），寫入／admin 時加強。**建議 a**——新手隨時看得到；agent 讀 stdout 不受干擾。
b. 只在寫入、admin、被拒絕時才出現，平常保持安靜。
c. 只在 `dbcli status` 之類的指令裡查。

**Q5　語氣與調性**：我建議「冷靜、精確、可信賴」，避免「熱情、口語、表情符號」。參考對象（皆為我記憶中的印象，本次未實際檢查）：`kubectl` 的 current-context 概念、`gh` 的錯誤附帶下一步指令、`psql` 的克制。錯誤訊息格式建議為：一行原因 + 一行脈絡 + 一行可執行的恢復指令，並保留穩定的錯誤代碼給 agent。你同意這三個形容詞嗎？

**Q6　訊息語言？**
a. 維持英文。**建議 a**——agent 與跨團隊使用最穩定，錯誤代碼也好搜尋。
b. 跟系統語系（可含繁中）。
c. 英文為主，`--help` 與 `init` 引導提供繁中。

**Q7　大量匯出的進度**：事先算總筆數（`COUNT`）可能很貴。
a. 預設不算：顯示已匯出筆數、大小、速率與經過時間，沒有百分比；能便宜取得總數時才顯示百分比。**建議 a**——不給假進度，也不為進度條多跑一次重查詢。
b. 一律先算總數，顯示百分比與剩餘時間。

**Q8　硬性約束確認**：需要支援 `NO_COLOR` 與無色彩終端、80 欄寬、Windows 終端嗎？淺色／深色終端都要能讀？**建議全部都要**，我會照這組約束設計顏色角色（顏色一律搭配符號，不單靠顏色傳意）。

你想先看東西的話，回「照建議」即可，我會把建議答案當成假設往下做，並在 SESSION 標記。

## 設計師 第 2 回合

收到。這一輪交出 GUI 概念的三個視覺處理（風格板），三者放在同一個比較頁，可以切換比較。

**範圍先說清楚**：這是隔離的概念原型，只用來討論，不代表 dbcli 要加 GUI。README 的「No GUI」仍然有效；要不要真的做，是產品範圍的決定，要走專案的規劃入口，我不會自己啟動。你在第 1 回合沒答的題目，我都照建議答案當作假設（人優先、語氣冷靜精確可信賴、介面文字用英文、匯出不顯示假百分比、淺色與深色都要能讀），已記在 SESSION。Q3 的事實已經納入：連線只有使用者取的名字，沒有環境欄位，所以概念裡顯示的是「連線名稱＋引擎＋權限等級」，不去猜哪個是正式環境；`prod` 只是一個名字。要能確實標出正式環境，dbcli 得先有環境欄位，這是新的資料契約，列為未決。

**怎麼開**：用瀏覽器開 `work/prototypes/style-tiles.html`（離線單檔，不需要伺服器），上方切換 1／2／3。三個處理的內容、資料、狀態完全相同：連到 `prod`（read-only）時被擋下的 UPDATE、上一次查詢結果（email 欄被黑名單遮蔽）、正在跑的匯出。`Switch connection` 會切到 `local`（read-write），用來看第二種權限狀態；匯出數字每秒跳動，`Cancel export` 可以停止。全部是樣本資料，不會送出任何東西。目前的版面是三個處理共用的暫定版面，不是結構提案，結構方向留到下一輪。

**三個處理**

- **1 卡片目錄**：每個連線是一個貼了標籤的抽屜，權限像蓋上去的橡皮章。橡木色外框，紫色印泥代表 read-only，綠色代表 read-write；資料用打字機字體 Courier New，介面文字用 Gill Sans，密度中等。最有辨識度，權限一眼就會被當成「蓋章的規定」。代價是 Courier New 在小字級偏細，長時間看大量表格比較累。
- **2 混音台通道**：連線名稱像貼在混音台上的膠帶標籤；有寫入權限時，「WRITE」燈會亮起，就像錄音前的 ARM 燈。深色、高密度、窄體大寫標示，匯出速率用電平表呈現（顯示速率，不是假的完成度）。最貼近開發者在終端機旁邊的使用情境，「能不能寫」直接對應到一盞燈。代價是只有深色；要支援淺色，得另外做一套對應版本。
- **3 機場指標**：頂端的黃色指標帶永遠告訴你「你在哪裡」，連線名稱用 40px 顯示，下一行指出要寫入該往哪走；被拒絕時出現紅色告示。白底、字體只用 Seravek，間距最寬鬆。最直接解決「新手不知道自己在哪個連線」這個痛點。代價是黃色帶很佔空間，整天使用時存在感偏強，密度也最低。

**我的建議：選 2**。理由是 dbcli 的使用者本來就在終端機旁工作，而「寫入權限＝ARM 燈」最精準地對應到 dbcli 的權限分級。3 的「下一步往哪走」引導句，三個處理已經共用，選 2 也會保留。

**我實際檢查過的**：用瀏覽器截圖看過 1440×900 與 1024×768 兩種尺寸（三個處理都沒有橫向捲動）、切到 `local` 的 read-write 狀態，以及鍵盤 Tab 的焦點框（三者都看得到）。照設計底線修正了幾項：同一畫面原本有兩個主要按鈕（被擋下時改由恢復動作領頭，Run 降為次要）、膠帶標籤上的灰字對比不足、提示訊息內文改回 16px 以上、左側清單原本用色塊左邊框標示目前項目（已拿掉）、長資料表名稱改為截斷並保留全名。
**還沒檢查的**：每個處理的另一種明暗配色、窄螢幕（暫定為桌面工具）、真人試用。目前只看過截圖，這不是可用性測試的證據。

截圖在 `work/screenshots/`：每個處理各有 1440、1024、local 狀態三張，焦點框三者合併在 `v1-focus-all.png`。
