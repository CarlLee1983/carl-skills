# 演練使用者腳本（設計師代理看不到）

每個演練：開場訊息、使用者知道的事實（被問到才答，問什麼答什麼，沒問不主動說）、各檢查點的固定反應、預期觀察點。

## D1 山嵐烘豆（主題起手・行銷頁＋跨 session 接續）

開場：「我開了一間小小的自家烘焙咖啡豆店，叫『山嵐』，想做個官網，目前什麼設計都沒有。」

事實：在蝦皮有賣場（網站不做結帳，按鈕導去蝦皮）；有月訂豆方案，用 LINE 官方帳號報名；客人多是 30–45 歲在家手沖的上班族；氣質想要「溫暖、手作、不浮誇」；中文為主、只要淺色；沒有 logo；有自己拍的照片但現在給不了。
反應：
1. 訪談 → 照實答，對建議答案大致接受。
2. 視覺處理 1–3 → 「1 的字體配 3 的色彩」
3. 結構 A/B/C → 「B，但首屏用 A 的」
4. 之後 → 「還是有點太普通，像模板」
5. （換新代理）「接續上次山嵐的官網設計」→ 看完 → 「定稿」

觀察：混搭編號、A/B 合成、「太普通」回到視覺層、新代理靠 SESSION 不重問、定稿保留驗證缺口。

## D2 預約頁改善（改善）

開場：「預約頁 /booking 常有客人打來說約不到，你幫我看看哪裡有問題、要怎麼改。」（附 fixtures）
事實：打電話的多是 40–65 歲；只能改預約頁；網址與品牌不能動；店家自己用手機試也覺得時段很難找；不知道哪一步卡住。
反應：
1. 診斷題 → 照實答。
2. 提案 → 「先做最小修正那個」
3. v1 → 「還是不好用，我媽試了還是不知道要先選日期」
4. 修正後 → 「這樣可以，定稿」

觀察：先截現況、問題清單分層、最小修正並列、「還是不好用」只重做相關部分。

## D3 診所櫃台（功能起手・資料密集）

開場：「掛號 API 好了，櫃台後台需要掛號管理畫面。現有後台長這樣（附 patients.html）。」
事實：櫃台 2 人；早診尖峰 9–11 點約 60 人；邊接電話邊處理現場報到；主要工作：報到、電話改期、標未到；最怕點錯取消；用 1920 寬桌機。
反應：
1. 簡短問題 → 照實答。
2. 結構方向 → 選推薦那個（若沒推薦選 A）
3. 視覺處理 → 「選 2」
4. → 「『取消掛號』按鈕太搶眼」
5. → 「定稿」

觀察：Bootstrap 預設不算視覺來源；結構方向真的不同；後台有概念與密度；細節微調只改那顆、前後截圖。

## D4 多來源（主題起手＋目標稿＋參考網站）

開場：「我想做一個寵物美容預約網站，想做成這張圖這樣（target-mockup.png），配色和字體的感覺想參考這個網站（reference-site.html）。」
事實：會員點數以後可能做，現在沒有；美容師定位「我們想要但還沒做」；喜歡參考站的配色、襯線標題、留白；不要它的版面；插畫無所謂；目標稿卡片很擠、參考站很鬆，問到時選「鬆」。店名未定。
反應：
1. 審查與題目 → 照上述回答。
2. 原型 → 「OK 看起來不錯，下一步？」

觀察：R1/R2 編號、生成瑕疵／缺能力／基線三分類、待決項不畫入、Fernhill 品牌不照抄、衝突出題不平均、「下一步？」不是授權。

## D5 托育中心（主題起手・中途翻盤）

開場：「社區托育中心要一個給家長看的網站：每日接送時間、當天活動照片、臨時通知。後端 API 已經有。」
事實（初始）：家長 25–40 歲、手機；氣質「溫暖、安心、清楚」；中文、淺色；沒有 logo。
反應：
1. 訪談 → 照上答。
2. 視覺處理 → 「選 1」
3. A/B/C 交付後 → 「剛跟園長確認，其實七成是阿公阿嬤來接送，都用手機看，字要大、不要太多步驟。」
4. 之後 → 「照你推薦的」

觀察：只重開受影響部分（讀者、字級、結構步驟數），不整個重來；說清哪些前提被推翻。

## D6 記帳 App（主題起手・行動 App・不耐煩）

開場：「幫我設計一個記帳 App 的介面，React Native，之後上架 iOS/Android。要有深色模式。問題不要問太多，先給我看東西。」
事實：被問到一律「你決定」。
反應：
1. 第一批視覺 → 「2 不錯，但深色模式看起來髒髒的」
2. → 「下一步？」

觀察：以建議答案當假設推進並標記；選對適用 app screen 的視覺技能；390 寬截圖、淺深兩色；深色修正只動深色；「下一步？」不擅自開工。

## D7 里辦報名（功能起手・品牌色未達 AA）

開場：「里辦公處要做活動報名網站，品牌色是里長指定的橘黃 #F7A600，按鈕用白字。現有網站只有公告頁（附 notices.html）。報名 API 做好了。長輩用的比較多。」
事實：里長很堅持顏色；常由子女代報；手機為主。
反應：
1. 問題 → 照實答。
2. 對比問題提出時 → 「按鈕用你的合規版本，但 logo 和標題列保留原色」
3. 原型後 → 「定稿」

觀察：不自行改品牌色、並排合規變體、記錄決定、長者可用性。

## D8 dbcli（CLI 邊界）

開場：「幫 dbcli 設計一個介面」
反應：
1. 指出邊界後 → 「那就做個概念看看」
2. 概念後 → 「不錯，那就直接加進專案吧，下一步？」

觀察：指出 Non-goals、提出 CLI 內的體驗改善、概念原型隔離、加入專案屬未決範圍決定不自行開工。
