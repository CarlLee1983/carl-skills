## 設計師 第 1 回合

我先確認理解，並先處理一個會影響所有畫面的問題：**橘黃底配白字，長輩看不清楚**。

**我的理解（可更正）**
這次是「功能起手」：已有公告頁和里長指定的品牌值（#F7A600、按鈕白字、里徽），要為新的報名功能設計介面，公告頁本身不改版。報名 API 只有三件事：看活動列表（含剩餘名額、截止、是否需攜伴）、報名（姓名、電話、人數，回傳報名序號）、用序號＋電話取消；沒有登入、付款、簡訊。所以最關鍵的一步是「報名完成後，長輩怎麼記住序號」，因為取消要靠它、系統也不會傳簡訊。品牌只固定了顏色、按鈕字色和里徽，字體、字級、間距還要另外設計。

**發現：品牌色對比不足（已截圖）**
白字放在 #F7A600 上只有 2.02:1，按鈕文字標準要 4.5:1、頁首大字要 3:1，兩者都不及格；橘黃按鈕對淡米色頁面底也只有 1.94:1，按鈕外框不明顯。對視力退化的長輩，這是會按不到、看不清的問題。我保留品牌色，做了兩個只改一個值的合規變體放在一起比較：

- 變體 1：按鈕保留橘黃，字改深褐 #3D2600（7.05:1）。但按鈕邊界仍不足，還得再加框線。
- 變體 2：保留白字，按鈕改成同一橘色調加深的 #9E6A00（4.65:1）。橘黃 #F7A600 繼續用在頁首色帶、里徽與重點色。

比較頁：`work/prototypes/brand-contrast-v1.html`；截圖：`work/screenshots/brand-contrast-v1-390.png`（手機）、`work/screenshots/brand-contrast-v1-1280.png`（桌機）。

**想請您決定的問題**（可直接回「Q1 是，Q3 改 b」）

- **Q1 按鈕配色**：建議 **變體 2**（白字＋深橘 #9E6A00），因為里長「按鈕白字」的要求原樣保留，橘黃仍是整站主色，且只改一個值就全部及格。若里長堅持按鈕必須正好 #F7A600，則選變體 1（字改深褐＋加框線）。原樣不改我不建議。
- **Q2 誰在操作**：建議以「長輩或子女用手機，一次報一筆」為主要情境設計，志工代報用同一個流程。若志工常在里辦用電腦一口氣幫很多人報名，畫面會改成連續輸入的櫃台模式，差很多，請告訴我。
- **Q3 和公告頁的關係**：建議同一個網站、共用頁首和里徽，公告頁加「活動報名」入口，有報名的公告（例如重陽敬老餐會）直接帶到該活動。另一種是獨立的報名網址（例如印在海報 QR code 上）直接進活動列表。實際上大家多半從哪裡進來？
- **Q4 序號遺失怎麼辦**：沒有簡訊，序號只會出現在完成畫面。建議完成畫面用大字顯示序號，並提供「列印」與「截圖保存」提示，同時寫上里辦電話作為後備。請問里辦是否接受長輩打電話請志工代為取消？這決定畫面上要不要把「打電話給里辦」列為正式取消方式。
- **Q5 攜伴活動**：API 有「是否需攜伴」。建議理解為「需要有人陪同」，報名時提醒並把人數預設為 2、仍可改。若它的意思是「必須至少 2 人」，表單要擋下 1 人的報名，請確認。

**開啟方式**：用瀏覽器開 `work/prototypes/flows-v1.html`。畫面底部的黑色長條是切換工具，不屬於設計：左右箭頭切換方向 A／B／C（電腦也可以按鍵盤左右鍵），右邊選單切換情境（正常、送出失敗、讀取中、沒有活動）。活動和序號都是示意資料，按送出不會真的報名。

**三個方向**（同一批活動、同樣的欄位）

- **A 活動牆**：像公告頁一樣一張張活動卡，能報名的排前面，額滿和截止收在最下面；點進活動頁，在同一頁填姓名、電話、人數就送出。好處是熟悉、一頁看完；代價是表單比較長，送出前沒有確認頁。
- **B 一次一問**：一進來先問「報名」還是「取消」，接著一頁只問一件事（哪個活動、幾位、姓名、電話），最後一頁確認，每一項都可以回去改。最適合長輩自己慢慢操作；代價是要按五步，子女或志工代報會覺得慢。
- **C 議程＋任務首頁**：首頁上方就有「取消報名」和「打給里辦」，活動依「這週末／下週／11 月」排成精簡列；填表前先問「幫誰報名」，選「家人或里民」時欄位說明會跟著改；報完可以直接按「再幫另一位報名這個活動」。最適合代報；代價是首頁比較密，列表上看不到地點。

三個方向的完成頁都會大字顯示序號，並寫明「不會另外傳簡訊」、提供列印。取消頁都把「打電話給里辦，志工可以代為取消」列為正式做法（照您 Q4 的回答）。

**我的建議**：選 **C**。您說最常是子女或志工代報，C 的「幫誰報名」和「再幫一位」正好對應；長輩自己用也只要點活動、填三欄。如果擔心長輩填錯，可以把 B 的確認頁加進 C，在送出前多一步。
