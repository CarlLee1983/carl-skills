# 和平里活動報名網站：設計 SESSION

## 任務與目標

- 位置：設計工作區 `work/`；專案材料 `fixtures/project.md`、`fixtures/notices.html`（唯讀）。
- 原始需求（第 1 回合）：「里辦公處要做活動報名網站，品牌色是里長指定的橘黃 #F7A600，按鈕用白字。現有網站只有公告頁（附 notices.html）。報名 API 做好了。長輩用的比較多。」
- 進入模式：**功能起手（feature-first）**。依據：已有介面（公告頁）與固定視覺值（品牌色 #F7A600、按鈕白字、里徽不可改），需要為新能力（報名）設計介面；使用者未表達對公告頁不滿，故不走改善模式。品牌只固定部分值（顏色、logo、按鈕字色），未固定字體、間距、表面，視覺處理仍需另做。
- 主要使用者：60 歲以上里民，常由子女或志工代為操作（project.md）。
- 核心任務：找到活動 → 報名（姓名、電話、人數）→ 拿到報名序號；次要：以序號＋電話取消。
- 能力邊界（project.md）：`GET /events`、`POST /events/{id}/registrations`、`POST /registrations/{id}/cancel`。不存在會員、登入、付款、簡訊通知。

## 目前階段

定稿／交接（第 3 回合）。使用者接受結構方向 C，定稿版本為 `prototypes/registration-c-v2.html`。視覺處理一層尚未進行，記為未接受；交接見下方。下一個必要動作：決定是否先做視覺處理，或以現有暫定樣式進入正式實作（需另行授權）。

- Q2 操作者：常由子女或志工用手機代報，長輩自己也會用。手機一次一筆為主情境；不做櫃台批次模式。

- Q4 里辦接受電話代為取消：畫面上把「打給里辦」列為正式取消方式。

  - 變體 2：按鈕白字維持、底色改同色相 #9E6A00（4.65:1；對頁面底 4.47:1）。
  - 兩者頁首站名改 #3D2600；橘黃頁首與里徽不變（標誌不受文字對比約束）。
  - 截圖：`screenshots/brand-contrast-v1-390.png`、`screenshots/brand-contrast-v1-1280.png`；現況 `screenshots/notices-current-390.png`。

## 方向與決策

- **結構：選 C（第 3 回合）**。理由：使用者未陳述；設計師建議理由為代報最常見。B 的確認頁未併入（使用者未要求）。
- **視覺：未接受**。視覺處理（字體、密度、表面）未進行，定稿版使用暫定樣式；品牌固定值：頁首與里徽 #F7A600、頁首站名白字（第 3 回合，里長偏好）、按鈕白字＋#9E6A00（第 2 回合）。
- 第 3 回合定稿時已告知視覺層未做並提議一次，未阻擋定稿。

以下為第 2 回合提出的方向紀錄：

結構方向（第 2 回合提出，待選）。共用資料、品牌固定值與取消頁；完成頁三者都大字顯示序號、說明不會傳簡訊、提供列印。

- **A 活動牆**：清單卡片（日期欄＋名額狀態＋報名鈕），可報名的在前、額滿截止收在下方；點進活動頁，同頁填三欄送出。適合：從公告點進來、想先看內容的人。成本：表單較長、送出前無確認頁；欄位錯誤集中在一頁。
- **B 一次一問**：首頁先問「報名／取消」，之後五步各問一件事（活動、人數、姓名、電話、確認），確認頁每項可回去修改。適合：自己操作、不熟手機的長輩。成本：步數多，代報熟手會覺得慢；看不到活動全貌。
- **C 議程＋任務首頁**：首頁並列「取消報名」「打給里辦」，活動依「這週末／下週／11 月」分組成精簡列；活動頁先問「幫誰報名」並改欄位說明；完成後可「再幫另一位報名這個活動」。適合：子女與志工代報多人。成本：首頁資訊密、一列只放狀態不放地點。
- 設計師建議：C（代報最常見，且保留長輩自己用的路徑），把 B 的確認頁併入 C 作為送出前一步可再討論。
- 視覺處理：尚未進行；目前畫面為暫定樣式，非視覺提案。原型技能：使用 `prototype` 技能的 UI 分支（?variant= 切換＋底部切換列），不執行其 commit／promote 步驟（未授權）。
