# 掛號管理畫面 設計紀錄

## 任務與目標

- 專案：安和家醫科診所櫃台後台（Laravel，Blade + Bootstrap 5 預設樣式）。素材：`../fixtures/project.md`、`../fixtures/patients.html`。
- 原始需求（第 1 回合）：「掛號 API 好了，櫃台後台需要掛號管理畫面。現有後台長這樣（附 patients.html）。」
- 進入模式：**功能起手（feature-first）**。依據：已有後台介面（patients.html），新增的是既有介面沒涵蓋的掛號功能；使用者沒有抱怨現有畫面。後台只有框架預設與零星手寫 CSS，沒有品牌或設計系統，**視覺來源不固定視覺**，選定結構後要另做視覺語言。patients.html 是現有介面，不是目標稿或參考網站。
- 主要使用者：櫃台人員 2 位（第 2 回合使用者說明）；櫃台螢幕 1920 寬（Q6 回答）。
- 負載：早診 9–11 尖峰約 60 人（三位醫師合計，使用者說明）。主要工作：報到、接電話改期、標未到；最怕點錯取消。
- 核心任務：病患到櫃台時找到他的掛號並報到；處理電話改期／取消；診次中處理過時未到。
- 範圍限制（有來源）：API 只有清單、報到、改期、未到、取消、可用時段。沒有新增掛號、撤銷報到、叫號看板、健保卡讀卡、簡訊、病歷。看診中／完成不是櫃台寫入的。

## 方向與決定

| ID | 概念 | 適合 | 代價 |
| --- | --- | --- | --- |
| A 時段清單 | 依時段排序的表＋篩選＋搜尋 | 查詢、最像 patients.html | 已結束的列堆在上面；找人靠篩選 |
| B 醫師看板 | 三位醫師各一欄 | 看各診進度 | 找人要掃三欄 |
| C 報到台 | 搜尋即報到＋需要處理欄 | 尖峰報到最快 | 一覽性最弱 |

- **結構選擇：C**（第 2 回合）。理由（使用者）：「報到很快，打名字按 Enter 就好」。
- **卡住的地方（使用者）**：一邊接電話一邊有人排隊，電話要改期時得離開報到畫面去找人。
- **C v2 結構變更**（回應卡點）：報到與電話拆成兩個獨立欄位，各有自己的搜尋與狀態，互不清空；電話欄先選日期再找人，在欄內展開改期（不開對話框）；右欄「已過時間未報到」的「改期」直接帶入電話欄。
- **防誤取消**（回應「最怕點錯取消」）：取消只出現在電話欄改期區下方，與報到、改期的按鈕分開；必須經過對話框，預設焦點在「不要取消」，確認鍵寫出病患姓名。標記未到改成原地兩段確認（按一下變「確定未到」，4 秒後還原），不開對話框。
- Q1–Q5 照建議（第 2 回合）：不做現場新增掛號、姓名為主搜尋、改期不換醫師、過時只標示不自動未到、報到不加確認（撤銷報到列為 API 缺口）。Q6：1920 寬。
