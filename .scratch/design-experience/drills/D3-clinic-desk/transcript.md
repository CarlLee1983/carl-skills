## 設計師 第 1 回合

這回合我交付三個可以點的「掛號管理」結構方向，讓你比較櫃台報到該怎麼進行；視覺（顏色、字體、密度）等你選定結構後再做 2–3 款比較。

**我的理解（請更正）**：這是在現有後台**新增**一個畫面，所以我以「功能起手」進行，沿用現有頁首與導覽，先比結構。現有後台只是 Bootstrap 預設樣式、沒有品牌或設計規範，所以視覺之後要另外決定。使用者是櫃台人員，最常做的事是「病患走到櫃台 → 找到他的掛號 → 報到」，其次是接電話改期／取消，以及診次進行中處理過了時間還沒來的人。API 沒有新增掛號、撤銷報到、叫號、讀健保卡、簡訊，所以畫面上都不會出現這些功能。

**原型**：`work/prototypes/comparison.html`，用瀏覽器直接開。上方深色列切換方向與情境（載入中、讀取失敗、報到失敗、被別台櫃台更新）。資料全是範例，現在時間設在 10/23（五）10:20 早診中，操作只在頁面內模擬，不會打 API。

- **A 時段清單**：一張依時間排序的表，篩選醫師／狀態加搜尋，每列主要動作是「報到」，改期、標記未到、取消收在「⋯」。最像現在的病患資料頁，最好上手；代價是早上 10 點時，已看完的列堆在上面，要往下捲才看到該處理的人。
- **B 醫師看板**：三位醫師各一欄，欄頭顯示看診中幾號、候診幾人，卡片上直接報到，已結束的收起來。最容易回答「還要等多久」；代價是找人要掃三欄，電話改期要先切到那天那個診。
- **C 報到台**：大搜尋框，打姓名或電話後按 Enter 就報到；右欄自動列出「已過時間未報到」可直接改期或標記未到，下方收著今日全部掛號。尖峰報到最快；代價是一眼看全天的能力最弱。

**我的建議是 C**，因為櫃台最頻繁、最有時間壓力的就是報到，而 C 把它變成「打字＋Enter」；B 的各醫師進度我已經放一個簡版在 C 右欄。

**試用任務**（可在任一方向做）：
1. 陳美玲到櫃台了，幫她報到。
2. 黃淑芬來電，明天（10/24）陳醫師午診要改到下週一下午。
3. 找出早診過了時間還沒來的人，處理掉其中一位。
4. 情境切到「報到時伺服器錯誤」，再報到一次，看你知不知道接下來怎麼做。

試完請分開告訴我：**喜歡哪裡**，以及**做主要動作時卡在哪裡**。

**需要你回答的問題**（可以只回「Q1 是，Q3 改 b」）：

- **Q1 沒有預約的現場病患怎麼辦？** API 沒有「新增掛號」。建議：這次畫面不做，找不到人時只提示「系統沒有新增掛號功能」；若櫃台每天都會遇到，請列為產品決定，要先補 API。
- **Q2 櫃台平常用什麼找人？** 建議：姓名為主、電話或病歷號為輔（三個方向都這樣做）。若其實多半是報號碼或看健保卡，C 的搜尋要調整。
- **Q3 改期能不能換醫師？** 建議：不能，只換同一位醫師的時段（API 只寫「新時段」）。若可以換，改期視窗要多一個醫師選擇。
- **Q4 「過了時間還沒來」怎麼處理？** 建議：過了預約時間就標出「已過 N 分」，但「未到」一律由櫃台手動按，不自動標記。
- **Q5 報到按錯怎麼辦？** API 沒有撤銷報到。建議：不加確認視窗（報到太頻繁），把「撤銷報到」列為 API 缺口；若你覺得按錯很常見，告訴我。
- **Q6 櫃台螢幕多大？** 建議：桌機 1280 寬為主，1024 也要能用（我兩種都檢查過）；若有平板或窄螢幕，B 會比較吃虧。

**已驗證**：用瀏覽器在 1280 與 1024 寬截圖檢查過三個方向，沒有橫向捲動；C 打字後按 Enter 報到、A 改期選時段、報到失敗重試、讀取失敗，以及 Tab 焦點都試過。**未驗證**：真人試用、比 1024 更窄的螢幕。另外，沿用的現有頁首導覽文字對比不足，等做視覺時一起提出。設計紀錄在 `work/SESSION.md`。

## 設計師 第 2 回合

這回合我依你的回饋把 C 改成 **C v2**，並做好三款視覺處理放在同一個畫面上比較。開 `work/prototypes/desk-v2.html`，上方深色列可以切換 1／2／3 和各種情境。

**結構上改了什麼（回應「接電話要離開報到畫面」）**：報到和電話現在是並排的兩欄，各自有搜尋框，互不干擾。櫃台有人排隊時，左邊照樣打名字按 Enter；電話一來，在中間欄先點病患說的日期（預設明天），打名字，直接在欄內選新時段、按「確認改期」，左邊打到一半的搜尋不會被清掉。右邊「已過時間未報到」按「改期」會直接帶到電話欄。1920 寬剛好三欄並排；窄一點的螢幕會變兩欄。

**防止點錯取消**：「取消」只出現在電話欄改期區的最下方，用虛線和報到、改期分開，按了一定會跳出確認視窗，預設停在「不要取消」，確認鍵會寫出病患姓名（例如「確認取消 黃淑芬」）。「標記未到」比較常按，所以不跳視窗：按一下會變成紅框的「確定未到」，再按一次才送出，4 秒沒按就還原。

**三款視覺處理**（結構、資料、狀態完全相同，都以現有後台的藍色為基礎）：

- **1 清晰帳冊**：延續現在後台的藍色頁首、冷灰底、細線分隔、緊湊。和病患資料頁最一致，櫃台不用重新習慣；代價是最不新鮮。
- **2 安靜診間**：暖白底、低彩度深藍、圓潤按鈕、面板浮起、字稍大、行距寬。長時間看最舒服；代價是 1920×1080 下一屏能看的列較少，電話欄的「取消」要往下捲才看得到。
- **3 叫號燈**：取候診區叫號燈的大號數字，深色頁首、粗框、狀態用實心色塊。尖峰時一眼最清楚；代價是畫面最重，和病患資料頁差最多。

**我的建議是 1**：櫃台兩個人整天在這個畫面和病患資料頁之間切換，一致比新鮮重要。如果尖峰時想更快看清號碼，可以回「1 配 3 的號碼」，我把 3 的大號數字合進 1。

**試用任務**：
1. 在左邊打「陳美玲」但先不要按 Enter；這時電話來了，黃淑芬要把明天陳醫師午診改到下週一下午。改完再回左邊幫陳美玲報到。
2. 把右邊一位過時未到的人標成未到，再試著取消黃淑芬的掛號，但在確認視窗按「不要取消」。

試完一樣請分開告訴我：**喜歡哪裡**，以及**做主要動作時卡在哪裡**。

**問題**：

- **Q1 選哪一款視覺？** 建議 1（理由如上）；也可以混搭，例如「1 配 3 的號碼」。
- **Q2 電話欄預設日期**：建議「明天」，因為打來改期的多半是之後的掛號；如果多半是當天打來說會晚到或不來，改成「今天」。
- **Q3 病患常常說不出掛號日期嗎？** 現在的 API 只能依日期查，所以要先選日期。建議先這樣做；如果常常說不出日期，需要後端加「依病患查掛號」的 API，我會列成需求。
- **Q4 要不要鍵盤快速鍵在報到和電話搜尋框之間跳？** 建議要（例如 F2 跳報到、F4 跳電話），接電話時不用碰滑鼠。

**已驗證**：三款都在 1920 和 1440 寬截圖檢查過，沒有橫向捲動；用腳本確認了左邊有搜尋時能在電話欄改期，在左邊按 Enter 報到後，電話欄的選擇還在。文字對比三款都符合 WCAG AA；第 1 回合提到的頁首對比問題，三款都已修正。**未驗證**：真人試用這一版、螢幕閱讀器。設計紀錄在 `work/SESSION.md`。
