# SESSION：小樹苗社區托育中心　家長端網站

## 任務與目標

- 專案：小樹苗社區托育中心家長端（材料：`../fixtures/project.md`）
- 原始需求（第 1 回合）：「社區托育中心要一個給家長看的網站：每日接送時間、當天活動照片、臨時通知。後端 API 已經有。」
- 進入模式：**主題起手**。依據：只有 Node.js 後端 API，無前端、品牌、logo、設計系統。
- 主要使用者：**七成是阿公阿嬤接送**，用手機看，要字大、步驟少。來源是第 4 回合使用者轉述園長確認，取代第 2 回合「25–40 歲爸媽、不用特別考慮長輩」的答案。其餘是爸媽。
- 核心任務（第 2 回合確認 Q1=a）：確認／登記今日接送（15:00 前），待處理通知優先打斷
- 範圍限制（有來源）：無聊天、繳費、成長報告、推播；登入為一次性簡訊連結

## 訪談

- 產品類型（推論）：功能型產品（家長端，非後台人員）。證據：API 全為任務操作（讀今日、登記接送、回覆已讀）。
- 已確定（第 2 回合）：主要任務是接送（Q1=a）；使用者為 25–40 歲父母、手機（Q2）；多孩家庭先預留同頁顯示，列待決（Q3）；手機為主、只做繁中、只做淺色、無品牌素材由設計提案（Q4）；氣氛形容詞為安心、清楚、溫暖，避免幼稚（Q5）；照片是老師隨手拍（Q6）；沒有參考網站（Q7）
- 設計假設：使用者停留不到一分鐘；無推播，所以通知要在開啟時置頂
- 訪談完成條件已達成。功能型產品的專屬題（例如使用頻率、密度）沒有另外問，因為主要任務和情境已足夠決定設計
- 留給產品決定：簡訊連結過期後怎麼重新進入（已設計畫面，流程待定）、15:00 後的中心聯絡電話、照片隱私範圍、多孩家庭、接送人是否只能從登記名單選（Q14）、長輩是否自己操作與簡訊連結發給誰（Q15）

## 方向與決策

### 視覺樣式（數字）

- 1「月台時刻」：路線藍頁首、月台黃作唯一主動作、等寬數字；簽名動作是當天時間線（距離與時間成比例，衝突站標紅）。**設計師建議**，因為最貼近接送主任務。
- 2「聯絡簿」：淺綠紙張色、紅筆色代表老師、藍筆色代表家長動作、明體標題；簽名動作是家長簽章欄，回覆已讀後蓋藍章，通知保留。
- 3「暖色卡片」：類別慣例（暖底、白卡、圓角、單一行動綠）。impeccable 的偵測器標出「米色底」警告，保留不改，因為這是該慣例本身的語法。
- 使用者選擇（第 3 回合）：**樣式 1**。理由是「喜歡那個時間線，很清楚」。試用回饋分兩項記錄：喜歡的是時間線；卡關的部分是「改接送看得懂，沒卡住」。
- 遙測 ping（`--kind assigned`）沒有送出，因為這是對外傳輸。
- 三個樣式共用暫定版面，順序為通知、接送、活動；這個順序還不是結構提案。

### 結構方向（字母）
