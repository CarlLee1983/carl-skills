# 03 視覺處理提前、混搭與品味基線

Status: ready-for-agent
State: open
Blocked by: 02

規格：[spec.md](../spec.md)。

## 任務

主題起手時，把「發展視覺語言」階段移到結構方向之前：以訪談結果做 3 個附一句概念、以數字編號（1／2／3）的**視覺處理**，採 style tile 形式（真實內容的 hero、代表元件、字級階層、色彩角色），截圖比較；沿用既有的截圖審看與「只換色盤算同一個」規則。選定後所有**結構方向**（A／B／C）套用它再比較。功能起手的順序不變。

回饋表擴充：「1 的字體配 3 的色彩」等混搭回覆，記錄取用部分、合成新的視覺處理並截圖檢查概念一致性；「選 B」類回覆依編號系統區分結構方向與視覺處理。

加入適用兩種進入模式的**品味基線**：原型與視覺處理不使用 emoji，不以文字箭頭等符號充當圖示或裝飾；介面元素使用具設計感的 inline SVG 圖示，來源優先為專案指定圖示集，其次為成熟的開源圖示集，不新增套件依賴；圖示線寬、填色與尺寸屬於視覺處理，同一原型內一致。延續紀錄增加選定的視覺處理與混搭來源。

## 驗收條件

1. 行為情境：主題起手完整流程——訪談後先比較 3 個視覺處理，選定後才比較套用它的結構方向；結構與視覺分開記錄。
2. 行為情境：「1 的字體配 3 的色彩」合成新視覺處理並截圖檢查一致性。
3. 行為情境：品味基線——功能起手與主題起手各產出一個原型，皆無 emoji、無文字箭頭充當圖示，圖示為風格一致的 inline SVG；專案有指定圖示集時採用它。
4. 回歸：「結構已選定、無固定視覺來源」改為功能起手限定並通過；「選 A」「太普通」在新編號規則下仍通過。
5. 提案品質判定與封裝檢查同 01，結果附加到同一份驗證紀錄。
