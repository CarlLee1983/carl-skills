### 3. 發現

**F1：SQL 注入｜High**

- 主體：已登入的低信任使用者。
- 輸入：可控制的 `req.params.id`。
- 控制：第 4 行直接插入 SQL 字串，缺少參數化。
- 邊界：請求資料進入資料庫查詢語法。
- 資源：`invoices` 資料。
- 結果：輸入 `' OR '1'='1` 可使條件恆真，改變查詢選取範圍；第 6 行回傳其中第一筆。
- 證據：`src/routes/invoices.ts:2–6`。
- 分類：OWASP 2025 A05 Injection；CWE-89（離線未核實）。
- 最窄修正：使用綁定參數，禁止輸入改變 SQL 結構。

**F2：缺少租戶授權｜High**

- 主體：租戶 A 的登入使用者。
- 輸入：租戶 B 的發票 ID。
- 控制：`requireLogin` 只驗證 session；查詢未使用 `req.user.tenantId`。
- 邊界：租戶 A → 租戶 B。
- 資源：其他租戶的發票。
- 結果：符合 ID 的發票直接回傳，違反 schema 所載隔離要求；無須 SQL 注入。
- 證據：`src/routes/invoices.ts:4–6`、`src/auth.ts`、`db/schema.sql`。
- 分類：OWASP 2025 A01 Broken Access Control；CWE-639（離線未核實）。
- 最窄修正：查詢同時限制發票 ID 與 session 提供的租戶 ID。
