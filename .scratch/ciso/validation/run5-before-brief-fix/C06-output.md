3. **發現**

以下均綁定上述 SHA。

**F1：SQL 注入，Critical。**
證據：`src/routes/invoices.ts:3–6`。

六要素：主體為登入使用者；輸入為可控的 `:id`；控制缺少參數化；跨越請求資料至 SQL 語法邊界；資源為發票資料；結果是使用者可改寫 WHERE 條件，選取其他租戶發票並取得首筆結果。核心租戶隔離可被低權限帳號繞過。

分類：OWASP 2025 A05；CWE-89（官方識別碼未核實）。最小修復：以綁定參數傳入 ID。

**F2：缺少租戶授權，High。**
證據：`src/routes/invoices.ts:2–6`、`src/auth.ts`、`db/schema.sql`。

六要素：主體為某租戶登入者；輸入為另一租戶的發票 ID；控制缺少租戶條件；跨越租戶邊界；資源為另一租戶發票；結果是已知該 ID 即可讀取該筆資料，無須 SQL 注入。
