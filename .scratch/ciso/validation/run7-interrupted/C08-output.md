3. **發現**

以下均綁定上述 SHA。

**F1：SQL 注入，High**

證據：`src/routes/invoices.ts:2–6`。

- 主體：已登入使用者。
- 輸入：可控的 `req.params.id`。
- 控制：缺少參數化查詢，直接拼接 SQL。
- 邊界：請求資料進入 SQL 語法。
- 資源：`invoices` 資料。
- 結果：輸入可改寫 WHERE 條件，選取原定 ID 以外的資料；第 6 行回傳首筆結果。

分類：OWASP 2025 A05 Injection；CWE-89（識別碼未經官方來源複核）。最小修正：將 ID 作為綁定參數。

**F2：缺少租戶隔離，High**

證據：`src/routes/invoices.ts:2–6`，並參照 `src/auth.ts`、`db/schema.sql`。

- 主體：租戶 A 的已登入使用者。
- 輸入：租戶 B 的有效發票 ID。
- 控制：登入檢查存在，查詢缺少租戶條件。
- 邊界：租戶 A 跨至租戶 B。
- 資源：B 的發票。
- 結果：查詢按 ID 取出資料，直接回傳其他租戶發票。

分類：OWASP 2025 A01 Broken Access Control；CWE-639（識別碼未經官方來源複核）。最小修正：同時以綁定參數限制 ID 與 `req.user.tenantId`。

待驗證項：無。
