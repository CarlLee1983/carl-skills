### 2. 判斷

設計中的元素與信任邊界如下：

| 流程與元素 | 邊界及依據 |
|---|---|
| 付款商 → 公開 receiver | 外部請求進入服務；第1、6行 |
| receiver → Redis → worker | 原始輸入進入內部處理；第2、3行 |
| worker → 正式資料庫 | 輸入驅動持有正式憑證的工作；第3行 |
| receiver → 物件儲存 | 外部內容進入90日保存區；第4行 |
| 支援人員 → 主控台 → 儲存內容 | 人員權限進入保存資料；第5行 |

以下皆為**假設性威脅**，無嚴重度或完成狀態。S／T／R／I／D／E 分別代表偽冒、竄改、否認、資訊洩漏、阻斷服務、權限提升。

| 元素／邊界 | STRIDE假設與依據 | 個別緩解；日後驗證證據 |
|---|---|---|
| 付款商→receiver | S：若未驗來源，可冒充付款商（1、6） | 驗簽並綁定原始內容；偽造請求拒絕測試 |
| 同上 | T：若缺完整性與時效控制，可改內容或重播（1、6） | 簽署內容、時間窗及事件去重；竄改與重播測試 |
| receiver→Redis→worker | T：若佇列可被非授權者寫入，可植入事件（2、3） | 限制生產者並驗證事件結構；佇列權限及拒絕測試 |
| 同上 | D：若無容量控制，大量事件可耗盡處理能力（2） | 限流、大小限制與背壓；隔離負載測試 |
| worker→資料庫 | E／T：若payload可決定越權操作，正式憑證可能放大影響（3） | 固定操作與業務授權、最小資料庫權限；越權事件測試 |
| 完整處理鏈 | R：若缺關聯紀錄，難追查誰觸發何種變更（1–5） | 記錄事件識別、驗證與處理結果；可串聯的測試紀錄 |
| receiver→物件儲存 | I：若payload含敏感資料且讀取過寬，可能洩漏（4） | 資料最小化、限制讀取及到期刪除；權限與生命週期測試 |
| 同上 | D：若大小與數量不受限，90日保存可能耗盡配額（4） | 配額與大小限制；隔離容量測試 |
| 支援人員→主控台→內容 | S／E／I：若身分或資料授權不足，可冒用或越權讀取（5） | 驗證人員身分並逐筆授權；跨權限拒絕測試 |
| 同上 | T：若原始內容以可執行格式呈現，可能操控主控台（4、5） | 以純文字安全呈現；惡意內容顯示測試 |

六類覆蓋補充：公開入口的I、E，佇列的S、I、E，以及資料庫的S、I、D，因協定、權限及處理細節未載明，暫無具體威脅依據；儲存區的S、T、E與主控台的D亦同。各流程的R均由處理鏈追溯假設涵蓋，這些缺口不代表已有防護。
