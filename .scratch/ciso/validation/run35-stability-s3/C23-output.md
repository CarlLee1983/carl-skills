此設計的主要威脅假設是來源未驗證的付款通知進入內部處理鏈；應先決定來源驗證、重送控制與資料存取邊界，再細化實作。

### 1. 範圍

評估 `ledger-api` 規劃中的 webhook，依據 `docs/design/payment-webhook.md:1–6`；文件修訂識別無此證據，目前沒有程式碼。

涵蓋付款商、公開接收器、Redis、worker、正式資料庫憑證、物件儲存及客服管理主控台。未檢查實作、部署設定、實際權限與付款商協定。

專案規則及安裝清單均未提供適用工具：**沒有找到底層資安技能、以基準做法完成**。

### 2. 判斷

資料流與信任邊界：

- 付款商 → 公開接收器：外部進入服務，來源驗證尚未決定（第1、6行）。
- 接收器 → Redis → worker：外部原始內容進入內部工作鏈（第2、3行）。
- worker → `reconcile`：使用正式資料庫憑證的高權限處理邊界；實際權限無此證據（第3行）。
- 接收器 → 物件儲存 → 客服主控台：內容保留90天，再供人員讀取（第4、5行）。

以下皆為**威脅假設**，不是已確認漏洞。每列依序考慮 STRIDE：冒用、竄改、否認、洩漏、阻斷服務、權限提升。

| 元素／邊界 | 六類威脅假設 |
|---|---|
| 付款商／公開入口（1、6） | 偽造來源；修改通知；缺來源紀錄難追溯；錯誤回應可能洩漏內容；大量請求耗盡資源；偽造事件可能觸發高權限工作 |
| 接收器／Redis（2） | 非授權生產者入列；訊息遭改寫；缺事件關聯難追蹤；原始內容被讀取；佇列塞滿；偽造工作被信任 |
| worker／資料庫憑證（3） | 假冒消費者；內容影響核對結果；缺處理紀錄難歸責；憑證或資料外洩；重送拖垮工作；外部內容濫用資料庫權限 |
| 物件儲存（4） | 非授權存取者冒用；留存內容遭修改；缺存取紀錄；原始內容洩漏；大量寫入耗盡容量；儲存權限越界 |
| 客服／主控台（5） | 帳號冒用；顯示內容影響操作；缺讀取稽核；讀取超出職務範圍；大量讀取影響服務；客服權限越界 |

各假設是否成立，取決於尚未提供的控制。建議及日後驗證證據：

- 入口：驗證付款商簽章、時效及事件識別，限制大小與速率；以偽造、過期、重送及超限 fixture 驗證。
- 佇列：限制生產／消費身分，驗證訊息結構、限制積壓並保留事件關聯；查閱權限設定與隔離測試。
- worker：事件不得決定任意工作或查詢；最小化資料庫權限、確保冪等；以重送及非法事件測試核對結果。
- 儲存／客服：確認敏感欄位、最小化留存、限制角色與資料範圍、安全呈現內容並記錄存取；以越權、刪除期限及呈現測試驗證。

### 3. 發現

無已確認發現；威脅模型不賦予嚴重度或完成狀態。

### 4. 分派
