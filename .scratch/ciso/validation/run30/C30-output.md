資料流與信任邊界：

- 付款供應商 → 公開接收器 → 內部 Redis（第1–2行）。
- Redis → worker → 正式資料庫（第3行）。
- 原始 payload → 物件儲存桶，保存90日（第4行）。
- 支援人員 → 管理主控台 → 已存 payload（第5行）。

### 4. 分派

以下為供採納的 brief，尚未實際交付或執行：

- **架構／設計負責人**：決定供應商驗證、重播防護、事件格式與授權。目標是不可信事件不得取得可信付款事件的權限。
- **`/implement`**：採納後實作簽章與時效驗證、冪等處理、輸入限制、佇列背壓及事件稽核。以隔離環境和假憑證測試偽造、竄改、重播及超量輸入；完成條件是拒絕無效事件且合法事件只生效一次。
- **環境負責人（具名承接者無此證據）**：提出佇列／儲存桶隔離、資料庫最小權限、保存刪除及主控台授權方案；環境或權限變更須使用者授權。

原始證據為設計第1–6行；各方案須附設定、程式及測試證據，交付後由 CISO 複審。
