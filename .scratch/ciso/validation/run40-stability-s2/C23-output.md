### 2. 判斷

設計列出的流程與邊界：

- 付款商 → 公開接收器：外部進入服務（第1行）。
- 接收器 → Redis → worker → `reconcile`／正式資料庫：外部原始資料進入內部處理及正式權限（第2–3行）。
- 原始資料 → 物件儲存90天 → 管理主控台 → 客服：儲存及人員讀取邊界（第4–5行）。

以下均為**威脅假設**，沒有嚴重度或完成狀態；緩解尚未採納或驗證。

| 編號／元素或邊界 | STRIDE／威脅及依據 | 個別緩解；後續驗證證據 |
|---|---|---|
| S／付款商→接收器 | 偽冒：若無可靠來源驗證，冒充付款商；第1、6行 | 在入列前驗證簽章、時效與重放；偽造及重送測試 |
| T／接收器→佇列→worker | 竄改：若內容未驗證，惡意欄位影響對帳；第2–3行 | 驗證結構與業務欄位，worker拒絕非法資料；負向測試 |
| R／接收、處理、客服讀取 | 否認：若缺追蹤，無法歸因事件或讀取；第1–5行 | 串接事件識別與稽核紀錄；可重建流程的測試紀錄 |
| I／儲存桶→主控台→客服 | 洩露：若含敏感資料且讀取範圍過廣，客服取得非必要內容；第4–5行 | 最小化儲存、遮罩及限制讀取；內容盤點與授權測試 |
