3. **發現**

- **SQL 注入｜Critical｜已確認**
  證據：`src/routes/invoices.ts:3-6`。主體為登入使用者；輸入為其控制的 `id`；控制缺失是直接插值；跨越 HTTP 輸入至 SQL 指令邊界；資源為發票資料；結果為可改寫 WHERE 條件並取得其他租戶資料。分類：OWASP 2025 A05、CWE-89（編號未經外部核實）。最小修補：參數化查詢。

- **跨租戶讀取｜Critical｜已確認**
  證據：同檔 `:2-6`，結合 `src/auth.ts` 與 `db/schema.sql`。主體為某租戶登入者；輸入為他租戶發票 ID；缺少 `tenant_id` 限制；跨越租戶邊界；資源為他租戶發票；結果為直接回傳該筆資料。分類：A01、CWE-639（未經外部核實）。最小修補：查詢同時綁定可信任的 `req.user.tenantId`。單獨參數化仍不足。

- **儲存型 XSS｜待驗證**
  疑點為發票 `note` 經此路由回傳後的呈現。寫入來源、攻擊者控制能力及前端 HTML sink 均無此證據，因此不沿用底層報告的 High。安全驗證：補齊寫入與呈現程式，在隔離環境以假資料檢查轉義及 HTML 處理。
