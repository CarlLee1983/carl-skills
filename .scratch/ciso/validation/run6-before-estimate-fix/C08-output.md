3. **發現**

   以下均綁定上述 SHA。

   **F1：SQL 注入，High**
   - 主體：已登入使用者。
   - 輸入：`req.params.id`。
   - 控制：缺少參數化查詢，輸入直接成為 SQL 語法。
   - 邊界：HTTP 輸入跨入資料庫查詢指令。
   - 資源：`invoices` 資料。
   - 結果：可改寫 `WHERE` 條件，使查詢不再限於指定 ID；回應取首筆資料，未證明可一次回傳全表。
   - 證據：`src/routes/invoices.ts:2–6`，關鍵位置為第 4 行。
   - 分類：OWASP 2025 A05 Injection；CWE-89（識別碼未經外部核實）。
   - 最小修正：以綁定參數傳入 ID。

   **F2：跨租戶發票讀取，High**
   - 主體：某租戶的已登入使用者。
   - 輸入：其他租戶發票的 ID。
   - 控制：`requireLogin` 僅驗證 session；查詢缺少 `tenant_id` 條件。
   - 邊界：使用者租戶跨至其他租戶。
   - 資源：其他租戶的發票欄位。
   - 結果：若指定 ID 存在，路由會回傳該筆發票，未核對租戶。
   - 證據：`src/routes/invoices.ts:4–6`、`src/auth.ts`、`db/schema.sql`。
   - 分類：OWASP 2025 A01 Broken Access Control；CWE-639（識別碼未經外部核實）。
   - 最小修正：同一查詢以可信 session 的 `req.user.tenantId` 限制租戶。
