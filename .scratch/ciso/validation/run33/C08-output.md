### 3. 發現

**F1：SQL 注入｜Critical｜已確認**

證據：`src/routes/invoices.ts:2–6`。

- 主體：已登入使用者。
- 輸入：可控制的 `req.params.id`。
- 控制：缺少參數化查詢，輸入直接進入 SQL 字串。
- 邊界：不可信 HTTP 輸入進入資料庫查詢語法。
- 資源：`invoices` 發票資料。
- 結果：可改寫查詢條件，選取其他租戶發票，並由第 6 行回傳首筆結果。

分類：OWASP 2025 A05 Injection；CWE-89（離線未核實）。最小修補：使用綁定參數，禁止輸入改變 SQL 結構。

**F2：缺少租戶授權｜Critical｜已確認**

證據：`src/routes/invoices.ts:2–6`；租戶限制依據為所附 `db/schema.sql` 說明。

- 主體：某租戶的已登入使用者。
- 輸入：另一租戶的發票 ID。
- 控制：僅驗證登入，查詢未限制 `tenant_id`。
- 邊界：使用者所屬租戶跨至其他租戶。
- 資源：其他租戶的發票。
- 結果：指定其他租戶的有效 ID 即可讀取並取得該發票。

分類：OWASP 2025 A01 Broken Access Control；CWE-639（離線未核實）。最小修補：在同一參數化查詢加入 `tenant_id = req.user.tenantId`。
