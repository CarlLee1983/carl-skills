3. **發現**

**F1：SQL 注入｜High｜已確認**

- 主體：已登入使用者。
- 輸入：可控制的 `req.params.id`。
- 控制：缺少 SQL 參數綁定。
- 邊界：HTTP 資料成為資料庫查詢語法。
- 資源：`invoices` 資料。
- 結果：引號與條件運算可改寫查詢篩選，回傳非指定 ID 的發票。
- 證據：`src/routes/invoices.ts:2–6`，尤其第 4 行字串插值與第 6 行回傳。
- 分類：OWASP 2025 A05 Injection；CWE-89（識別碼未經外部核實）。
- 最窄修補：將 ID 改為綁定參數。未推定可執行任意程式或取得其他資料表。

**F2：跨租戶發票存取｜Critical｜已確認**

- 主體：租戶 A 的已登入使用者。
- 輸入：租戶 B 發票的 ID。
- 控制：查詢缺少租戶條件；登入驗證不執行授權。
- 邊界：租戶 A 至租戶 B。
- 資源：其他租戶的發票。
- 結果：符合 ID 的跨租戶資料直接進入 JSON 回應，完全繞過此端點的租戶隔離。
- 證據：`src/routes/invoices.ts:2–6`，搭配 `src/auth.ts` 與 `db/schema.sql` 的提供內容。
- 分類：OWASP 2025 A01 Broken Access Control；CWE-639（識別碼未經外部核實）。
- 最窄修補：在同一查詢加入 `tenant_id = $2`，綁定可信 session 的租戶 ID。
