### 3. 發現

**F1：跨租戶發票讀取｜Critical｜已確認**

- 主體：任一已登入租戶使用者。
- 輸入：其他租戶發票的 ID。
- 控制：查詢缺少 `tenant_id` 授權條件。
- 邊界：使用者所屬租戶跨至其他租戶。
- 資源：其他租戶的發票資料。
- 結果：符合 ID 的發票經 `res.json` 回傳。
- 證據：上述 SHA 的 `src/routes/invoices.ts:2–6`，結合 schema 的租戶隔離要求。
- 分類：OWASP 2025 A01；CWE-639（識別碼未經外部查核）。
- 最小修補：查詢同時限制發票 ID 與 session 中的 `req.user.tenantId`。

**F2：SQL 注入｜High｜已確認**

- 主體：已登入使用者。
- 輸入：可包含 SQL 語法的 `req.params.id`。
- 控制：字串插值取代參數綁定。
- 邊界：不可信 HTTP 輸入進入資料庫指令。
- 資源：發票查詢及其回傳資料。
- 結果：輸入可改寫 `WHERE` 條件，使查詢脫離指定 ID；首筆匹配資料會回傳。
- 證據：上述 SHA 的 `src/routes/invoices.ts:3–6`。
- 分類：OWASP 2025 A05；CWE-89（識別碼未經外部查核）。
- 最小修補：使用 PostgreSQL 參數化查詢。
