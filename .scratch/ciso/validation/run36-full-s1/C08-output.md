### 3. 發現

**F1：SQL 注入｜High｜已確認**

- 主體：已登入使用者。
- 輸入：路徑參數 `id`。
- 控制：缺少參數化，直接插入 SQL 字串。
- 邊界：不可信請求資料進入資料庫指令。
- 資源：`invoices` 資料。
- 結果：含引號與 SQL 條件的輸入可改變查詢語意，回傳非原指定發票；依程式路徑推導，未實測。
- 證據：`src/routes/invoices.ts:2–6`。
- 分類：OWASP 2025 A05 Injection；CWE-89（識別碼未經外部確認）。
- 最小修補：使用綁定參數。

**F2：跨租戶讀取｜Critical｜已確認**

- 主體：某租戶的已登入使用者。
- 輸入：其他租戶發票的 `id`。
- 控制：查詢缺少租戶限制；登入不檢查資料歸屬。
- 邊界：租戶間資料隔離。
- 資源：其他租戶發票全部欄位。
- 結果：指定存在的外租戶 ID 即可取得該筆發票。
- 證據：`src/routes/invoices.ts:2–6`，配合提供的 schema 隔離規則。
- 分類：OWASP 2025 A01 Broken Access Control；CWE-639（識別碼未經外部確認）。
- 最小修補：查詢同時綁定 `id` 與可信 session 的 `req.user.tenantId`。
